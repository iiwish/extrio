# Extrio 第一版前端原型合同

## 1.0 交付范围

1.0 的交付范围为单组织自托管稳定版，面向一个组织内的数据运营团队，保留本地账号角色、SQLite 评估和 PostgreSQL 部署路径。多租户、SSO/MFA、分布式高可用和移动端不属于本次交付范围。全站页面的内容组织、桌面布局、操作流程和状态反馈属于 1.0 的体验验收范围，不以功能测试通过或单纯调整样式代替。具体页面方案需以真实界面走查和用户复核为依据，沿用唯一正式前端。

1.0 的功能、AC/NFR、部署依赖和退出条件以[单组织自托管验收范围](planning/v1.0-scope-matrix.md)为版本适用合同。功能实现、工程验证、页面设计签收和生产目标达成分别记录，不将范围确认视为已实现或已验收。

## 运营状态与处理入口

首页与来源列表共享当前来源待处理分类，纳入首次待运行、待审核、待生成、待完成迁移、活动规则缺失、最近运行不可用及最近终态异常。归档来源和实际执行中的来源不计为待处理；历史异常不替代最新运行。字段目标尚未开始迁移的未对齐来源在需求详情独立呈现，不从首页待处理数量推断全部需求已达成。

需求详情默认字段分区即可看到目标版本、活动来源未对齐数量及版本未知数量；归档来源不计活动对齐，未知不显示已对齐。查看对齐只切换来源分区，保留筛选和字段草稿，不发起迁移。来源概览独立显示规则资格、最近结果与持续更新状态，展示真实调度开关、频率、时区及下次运行，未开启时明确仅手动、不自动更新。

运行成功不代表采集范围完整，达到页数上限的正常终止保留结果与范围未确认提示。部分成功分开呈现质量拒绝和未获取页面；本次拒绝筛选保存在 URL，展示该运行返回的拒绝记录，记录不全时明确已加载数量。获取与访问问题先进入执行诊断，字段质量或明确结构问题可查看规则证据；任何导航均不自动重跑、修订或发布规则。

## 体验设计评审

模型设置使用默认模型工具栏与供应商分组面板，供应商身份、凭据状态和模型行分层展示，复用 DetailPanel。编辑弹窗统一尺寸，保存与删除失败在弹窗内反馈；密钥隐藏、权限与删除确认保持有效，不模拟连通性测试。

系统设置以统一白色面板呈现偏好与账户、实例运行状态、采集策略和用户管理；复用 DetailPanel，保持紧凑指标与稳定用户列宽。权限、安全策略及账户操作保护沿用既有行为，模型分区独立验收。

新建来源使用来源列表上的宽弹窗，表单内部滚动、操作栏吸底；保留需求归属、批量 URL 校验、文件导入和部分成功结果。格式说明按需展开，未保存关闭沿用离开确认，提交中禁止关闭；单条成功进入来源详情，批量导入保留结果页。

新建需求使用需求列表上的创建弹窗，仅填写需求名称和采集目标；底部操作为取消与创建需求。弹窗最大宽度 640px，直接访问 /collections/new 也显示列表与弹窗。点击遮罩不关闭，提交中阻止关闭；保留权限、校验、失败重试及幂等保护，成功后进入需求明细。编辑弹窗仍使用保存需求语义。

数据明细复用 DetailPanel 和运行详情导航样式。正文区将正文/HTML 切换集中在面板标题栏，摘要采用紧凑事实区；版本观察、质量决定、来源谱系保持独立分区，来源链接采用无嵌套卡片的信息行。长标题、URL 和差异内容支持换行；HTML 仅以惰性文本或转义源码显示，不执行采集内容。

AI 任务详情与采集运行复用 DetailPanel 和运行详情样式，统一结果、执行过程、模型调用、证据四个分区。结果摘要集中展示调用量及验证计数，产出与审核单独呈现；过程页保留预算摘要和阶段记录，逐页读取数据置于证据页。模型列允许长名称换行，失败和运行中的尝试使用对应图标。技术标识保持按需展开，不展示敏感提示词或响应正文。

产品体验成熟化的 P0/P1 技术验收通过。P2 的来源 URL 配置子项已获用户确认并实现，其余设计样板处于用户评审状态，见 [P2 设计合同](design/product-maturity-p2/design.md)；需求内数据查询、样本证据工作区和分组处置目标不作为当前已实现能力，其余 P3 实现须经对应页面方案确认。

来源详情以 URL 配置为主任务：普通状态默认「采集配置」，待审核默认「规则审核」，显式 section 深链接优先。采集配置首位展示完整入口 URL、复制/打开/编辑，其后是采集说明与需求归属、定时运行、采集范围；数据合同和推送投递按需展开。「运行与结果」承载既有运行摘要；「规则与证据」承载审核、验证和直接展示的规则工作区。URL/意图修改沿用现有保存确认、规则失效、关闭调度、权限与并发保护，不自动执行采集。实现与验证见 [来源 URL 工作区](planning/source-url-workspace.md)。 三个分区统一使用白色、浅边框、8px 圆角的工作面板和 16px 分区间距；规则工作区不提供折叠入口。 页头仅保留状态主操作、执行日志和管理菜单；AI 修复位于规则操作区，证据包导出位于分区底部。

采集运行详情保持结果、执行过程、范围与增量、质量与证据四个分区。运行面板与来源规则工作区共享 DetailPanel，统一白底浅边框和 8px 圆角。执行指标及阶段记录使用留白分组；质量与证据不嵌套卡片，技术标识按需展开。终止原因、权限、取消确认状态、拒绝结果筛选和证据真实性沿用领域行为。

需求、来源、采集运行、AI 任务和数据列表共享 ListWorkspace、ListPagination 与 useListQuery。工具栏、数量、错误提示和底部分页栏固定；列表填满窗口剩余高度并独立滚动，表头吸顶，宽列仅在列表区域横滚，详情页保持独立的文档滚动模式。底栏显示当前行范围、筛选总行数、每页行数、当前页、总页数及首页/上一页/下一页/末页和跳页控件；每页可选 20/50/100/200 行，默认 50。页码与条件写入 URL，筛选、排序、视图和页大小变化回到首页，换页替换行并重置纵向位置，刷新与详情返回保留页码，超界页回落到末页。数量来自服务端全量统计，不以当前页或前 200 条推算；未知数量不显示零，刷新失败保留旧数据并标记未刷新。需求列表采用紧凑行、单行说明摘要和按需可读的完整名称/合同。运行与 AI 历史使用数据库计数与分页；需求和来源复用领域汇总模型在服务端筛选分页，来源附带当前页各来源的精确最近运行。实现合同见 [统一列表分页](planning/unified-list-pagination.md)。

需求明细以名称和采集目标为首屏主体，来源发布覆盖与当前生效字段版本集中呈现，版本对齐提示独立于来源规则发布状态。字段工具菜单统一承载模板、AI 建议与来源字段导入，版本历史为具名图标入口，编辑和发布操作保持可见；关联来源表按来源、状态、版本对齐、输出字段数和管理操作设置五列。详情保持文档滚动，完整目标可展开，权限、发布确认、迁移确认与未保存草稿保护保留。逐页优化范围及实现合同见 [详情页逐页打磨](planning/detail-page-polish.md)。

需求字段提示区分“尚未应用最新字段要求”与“版本无法确认”，已知未应用时说明来源仍按原规则采集、不会自动更新。来源覆盖只表示包含字段的来源数量，不证明约束或版本一致。来源详情的入口 URL 使用独立工具区，来源说明与需求归属并列，定时运行与采集范围在受支持桌面尺寸下并排展示；数据合同和投递记录保持按需展开。

## 自托管可靠性

运行正常达到配置页数上限且没有拒绝记录时记为成功，保留 max_pages 停止原因，结果页明确数据已保存；不显示等待处理或修订规则入口。有拒绝记录或抓取异常时保留异常处理状态。按页数完成不等于完整遍历时间范围，因此该停止原因不推进增量水位，避免跳过尚未遍历的数据。

列表发现与运行共用下一页地址解析：支持普通 href 和受限的静态 location.href 字符串赋值（可包装 encodeURI），不执行页面脚本。可识别的下一页必须通过发现阶段验证，不能以关闭分页或错误的查询参数分页规避；任务证据以具体分页错误码和字段路径呈现失败原因。

API 存活与实例可工作分开表达：`/healthz` 只报告存活，`/readyz` 检查同库 Worker 心跳、代码/合同/共享配置一致性及已使用密钥状态；设置的系统页提供真实 Worker、队列和恢复原因，不以读取失败显示健康。运行页按持久化 Operation 轮询，工程师或管理员可取消；运行中先显示取消已请求，只有持久终态才显示停止。失败原因按网络边界、访问、结构、预算和实例问题给出操作提示，不静默绕过授权或发布修复规则。

Run、Items、Checkpoint、Operation、Webhook 入队和 job 完成在有效租约事务内提交；过期 Worker 不得提交结果或错误，取消/超时不推进 Checkpoint。Webhook 使用稳定 Delivery ID、独立租约和有限重试；人工恢复保留历史，不因地址版本变化静默改投。单组织认证保护首次/最后管理员、角色边界与会话撤销，规则证明使用实际发布主体，不宣称四眼审批。

本地证据按 available/missing/expired/corrupt 等真实状态展示；sampled/metadata_only 不启用等价回放，失败终态不自动显示结果集已冻结。Worker 定期清理到期 raw，保留 manifest 摘要。全量离线备份包括 SQLite/PG、Artifact、当前签名 key 和完整凭据 keyring，恢复只接受空目标；缺失密钥和半恢复不得通过自动生成密钥或清除保护标记变成成功。密钥轮换保留可解密代际和历史公钥。

支持范围、HTTP/浏览器限制、双数据库恢复、安装/readiness、API/MCP 交接与停止方法见[自托管运维手册](self-hosted-operations.md)。固定来源样本和短期基准不等于外站/真实模型验收、月度 SLA 或 RPO/RTO 达标。本次发布按用户 2026-09-15 的决定豁免 72 小时观测门槛，不声明持续观测通过；用户设计与产品签收独立。

API 与 Worker 的初始化按数据库串行执行：SQLite 同机文件锁覆盖首次 WAL 设置、迁移和补齐；PostgreSQL 会话锁覆盖迁移和补齐。并发启动不得重复执行迁移或使 Worker 因建表冲突退出。

审核字段样本来自实际提取结果，验证样本计数使用真实预览记录；发布确认展示当前登录主体。需求字段与活动版本一致时标识为已发布字段，未保存编辑仍作为草稿。投递记录在配置面板可见期间每五秒刷新，空列表也能发现后台新交付；页面失焦时不持续后台轮询。

## 自适应网页证据

无进展停止包括重复调用与验证纠错：同一证据下连续三次纠错未解决任何已有问题时停止，不把改写提案说明视为验证进展。内部交接 URL 不作为业务输出缺失展示。

模型编辑对话框提供“自定义模型预算”复选项与上下文窗口、最大输入、最大输出、推理预留四个整数输入。默认展示禁用的保守默认值；启用自定义后显式配置，关闭后恢复默认路径。编辑供应商、切换默认模型或启停模型的全量配置提交必须保留其他模型的 limits，旧配置无该字段仍可读写。权限、加载失败与提交中的保护沿用模型设置工作流。

AI 任务的执行过程展示网页证据阶段、调用次数、输入/输出 token、耗时上限、计数方式与预算来源；证据页同时提供可展开的最近读取记录，包含 pageId、nodeId、动作、范围和片段末尾状态。页面级表格分别显示索引节点、已读节点与已读片段字符，不绘制语义准确率。完整样本验证通过与尚未通过明确区分，预算耗尽有中英文停止原因；历史任务没有该诊断时不伪造数据。读取记录不显示网页正文、原始提示词、模型思维过程或凭据。

界面使用现有无外框区段、紧凑指标和表格，不增加独立原型、聊天入口或移动端布局；验收覆盖中英文的 1440x900、1280x800、1132x1028、1024x800。

新任务调用上限为 16，发现阶段为后续编译与校验保留 4 次；历史任务显示原预算。发现额度耗尽与连续三次无新证据或新提案分别显示中英文停止原因，不表示模型供应商故障，也不把预留额度显示成已消费。输入、输出和时间安全上限保持独立。

## 核心操作上下文

规则审核的字段警告逐项显示字段标识、验证问题与“修复此字段 / 查看证据”操作，并说明样本缺失不等于来源没有内容。修复入口自动带入当前字段与警告作为本次说明，经确认后调用既有 AI 修复任务，保留输出合同与人工发布门。工程师/管理员以外角色、归档来源、活动任务与待迁移状态不能发起修复。取消不提交；请求失败保留修复说明供重试，不自动排除字段或接受风险。可选字段排除后不再输出；接受风险不会补齐缺失值，界面不承诺修复必然成功。

来源、运行、AI 任务和数据详情通过安全的站内 returnTo 保留入口筛选及 section 分区，返回不丢失来源页面的上下文。搜索可独立清除，刷新保留筛选；首次读取失败提供重试，不显示伪空列表，后台错误保留已读取数据。运行时间使用持久化 ISO 时间，不把历史运行显示为“刚刚”。正文中的 HTML 仅以惰性解析后的纯文本阅读或转义源码显示，不挂载源站脚本、图片和 iframe。来源概览区分已发布规则与最近异常运行；只读角色不能触发来源执行、定义/规则/策略修改或 Webhook 发送。接入表单的录入和导入预览具有离开确认，刷新/关闭使用原生未保存提醒；提交失败保留输入，成功创建可进入详情。设置弹层关闭后恢复原操作按钮焦点，退出失败保留会话并可重试。

## 来源生命周期与所属需求

来源支持需求内新增、基本信息编辑、保留历史的来源删除、归档恢复和独立的所属需求调整。工程师与管理员可执行管理命令，审核发布沿用现有角色边界。来源列表与详情、需求关联来源表提供统一管理菜单；列表默认仅显示活动来源，已归档筛选与搜索、需求条件一起写入 URL。归档来源在需求详情仍可追溯，但不计入可执行来源覆盖。

生命周期 `active|archived` 与规则探索/发布状态分离。归档原子关闭调度，禁止探索、修复、发布、运行与执行配置修改；恢复不启用调度、不启动任务或重发历史投递。实际排队、已领取、运行中的任务及未完成字段迁移阻断归档、删除、定义编辑和归属调整。调度领取后创建运行前再次验证来源状态。

删除来源不可恢复，但不删除规则、运行、数据、操作、AI 任务、证据、策略、调度历史、Webhook、投递或历史归属。已完成的历史不阻断删除；排队或执行中的任务、未结束运行和未完成迁移阻断。删除原子关闭调度、写入不可恢复墓碑，将来源从列表、需求关联与来源统计排除，并释放 URL。重新添加同一 URL 创建独立身份，不继承旧规则、数据、调度或 Webhook。归档可恢复且保留 URL 占用。

删除弹窗显示最新名称、URL、保留的历史数量及操作影响；只有最新预览允许删除时才显示名称确认输入，阻断时显示实际原因与处理方式。重新加载预览后重新输入名称确认。历史运行、AI 任务和数据标记“来源已删除”，保留内容与证据访问，不提供已删除来源的跳转、审核、修复或执行入口。已有投递仍按原合同处理，不因来源删除重发或取消。

基本信息编辑使用 managementRevision 乐观锁；仅改名保留规则，修改采集意图或规范化入口则关闭调度，清除候选、活动规则与 Checkpoint，后续需重新探索、审核发布。所属需求通过独立的目标选择、字段差异和影响预览确认，不混入基本信息编辑。目标必须是不同的活动需求，确认固定目标版本、revision 和全部差异；来源采用目标意图，历史规则、运行、数据与投递 payload 不重写，Webhook 配置保留。

Run、AI 任务、Operation 和 Item 的历史需求归属来自独立不可变记录，以 `collectionAttribution` 返回，不能用当前来源归属解释旧记录。已有历史的来源调整归属后停止调度并撤销旧规则的后续执行资格，新运行须重新探索、审核发布。无法可靠还原历史归属时列出具体记录并阻断调整，不猜测回填。列表、详情和两侧需求缓存同步刷新；提交中禁止重复操作和关闭，失败保留输入并复用幂等键，预览过期明确重载，删除从详情返回原筛选列表。

## 数据查询与导出

数据页使用 `GET /items?view=entities&page=N&limit=50`，服务端按 `collectorId + 历史 collectionId + entityKey` 选择最新观测后应用筛选，返回匹配实体总数、全局筛选选项和 `pagination` 页码元数据。页面采用服务端 LIMIT/OFFSET 换页，不累计前页；默认每页 50 行，可选 20/50/100/200 行。固定底栏由通用 ListPagination 展示当前行范围、总行数、每页行数、当前页与总页数、首页/上一页/下一页/末页及页码输入跳转。`page` 和 `pageSize` 写入 URL，详情返回保留页码；筛选或页大小变化回到首页，刷新保留当前页，换页重置列表纵向位置。超界页回落末页，空结果为第 1/1 页、0 行；读取失败显示错误与重试，不把前页内容冒充目标页，缺失元数据不虚构行数与页数。`q` 对标题、正文、来源名称和 entity key 做字面子串搜索，`sourceHost`、`collectorId`、`decision` 为精确筛选。CSV/JSONL 导出复用相同实体视图和全部筛选，覆盖匹配全集而非当前页，超出上限明确拒绝。默认 API 提供观测视图，保留 cursor/limit 兼容；page 与 cursor 互斥，entityKey 为精确匹配。分页为实时视图，不承诺跨请求快照或深 OFFSET 恒定耗时。桌面工具栏可收缩，分页和导出在最小支持视口可达，宽表格仅在自身区域滚动。

字段变更比较保留 JSON 类型，`null`、`0`、`false`、空字符串、空数组和空对象不合并为同一值；对象键顺序和数值等价表示不制造 Revision。有效变化追加 Revision 并进入已配置 Sink 的交付队列，不重写历史结果。

## 字段版本与受控迁移

字段草稿、不可变 CollectionVersion 和来源活动 RuleVersion 是三个独立状态。工程师或管理员可编辑草稿、应用模板和请求字段建议；审核者或管理员可发布字段版本、审核并启动或放弃来源迁移。字段发布冻结字段列表、JSON Schema、去重标识、变更检测字段及完整语义摘要；至少包含一个必填去重字段和一个变更检测字段。发布使用预览时的 revision、幂等键和原子审计，历史版本只读。有来源、已发布版本或字段建议审计历史的需求禁止物理删除，可归档。

新来源在创建时绑定需求活动字段版本，后续修改草稿或发布版本不会修改该绑定。尚无已发布版本的需求保留旧静态合同兼容路径，不将草稿视为已发布合同。固定版本的编译、预览、人工发布和运行使用同一不可变合同；缺失、跨需求或不匹配的版本不能静默回退。规则修复保留固定合同，运行不能由模型或可变草稿扩展业务字段。

来源迁移计划固定目标版本、差异及摘要，逐项确认所有字段增删改；运行、编译或审核操作进行中时禁止切换。确认迁移仅创建待重编译状态，当前绑定和活动规则保留；候选须通过重新生成、预览、审核和人工发布，发布事务才切换版本。失败显示真实原因，可重试或明确放弃。放弃不修改活动规则；来源定义未修改时恢复迁移前候选与审核状态，定义已修改时清除不适用候选并要求重新生成。旧版本和历史运行不重写。

内置公共公告、产品目录、活动日历模板使用稳定版本标识，预览展示字段差异，确认后替换保存的草稿而不发布。AI 字段建议复用默认模型供应商及网关，通过独立持久任务队列由 Worker 执行，不伪装为来源 AI Run。模型输入仅为需求名称、最多 4000 字目标及最多 50 个草稿字段的受限摘要，不发送网页样本或凭据。每需求最多一个活动任务、每小时最多五次请求；模型输出须通过 1–32 个字段的结构和语义校验。任务有 120 秒租约、最多三次领取及尝试 fencing，模型调用有超时与成功/失败、usage、摘要审计。

字段建议入口保留最近 20 个任务及排队、生成、失败、可选择、已应用状态，刷新恢复持久结果。建议完成不自动修改草稿，用户逐字段选择后按 key 合并；过期 revision 拒绝应用，失败保留选择及本地输入。未保存本地字段编辑时禁止模板和建议应用入口。字段版本、模板、建议与迁移界面共用正式前端，中英文桌面验收范围一致。

## 单前端实现边界

需求详情的“添加来源”在当前页面打开弹窗，固定提交当前 Collection ID，不提供切换或新建需求选项。支持逐行输入多个精确列表页入口，校验无效与重复地址；创建成功后刷新需求详情、需求列表和来源列表，并定位“关联来源”。部分失败明确显示逐项原因，仅保留失败入口供重试；请求失败保留输入，同一请求重试复用幂等键，提交期间禁止关闭，放弃输入需确认。已有来源不按需求名称自动迁移，重复地址由服务端明确拒绝；该入口不自动探索或发布来源。文件批量导入保留在采集来源工作面。

Extrio 只有一套正式前端：`web/index.html` → `src/main.tsx` → `app/router.tsx`，共享 AppShell、AuthGate、QueryClient 与 API 客户端。一级导航为概览、采集需求、采集来源、运行、数据、设置。需求列表读取独立持久化的 Collection，点击进入 `/collections/:collectionId` 明细，展示完整目标、字段要求、来源执行合同与关联来源；明细支持添加来源，来源归属链接返回需求明细，需求列表的搜索、状态筛选和更新时间排序通过 URL 保留，详情返回不丢失列表上下文。需求列表把名称与两行目标摘要放在同一业务单元，按来源发布覆盖、最近更新时间和合同引用进行比较；使用中、已归档和全部筛选显示各自数量，清除搜索只清除关键词，刷新保留当前条件。初始加载与失败不显示零需求，空列表、当前状态为空和搜索无匹配分别提供反馈。合同引用与来源发布覆盖不代表统一字段版本已冻结、调度开启或运行健康。需求支持独立新建、名称与业务目标编辑、空需求删除、归档和恢复；工程师与管理员可操作，其他角色只读。有关联来源的需求禁止删除；归档禁止编辑需求与添加来源，不停止已有来源、定时采集或运行，不删除历史数据。编辑使用 revision 冲突校验，不覆盖已有来源采集说明及不可变规则；新来源使用当前业务目标。模型、凭据、审核、运行与数据保留现有后端能力。旧 `experience.html` 地址仅用于兼容跳转，不提供独立应用或模拟业务数据。

需求详情以“采集字段 / 关联来源”组织工作面，字段仅展示一次。头部集中需求身份、使用/归档状态、来源发布覆盖与更新时间，长目标或多段目标支持摘要与全文展开。当前分区通过 section=sources 写入 URL，采集字段为默认分区；刷新恢复分区，返回列表保留 q/status/sort 且不携带详情 section。字段名称、技术标识和业务说明归入同一列，编辑操作列固定宽度；来源覆盖和约束差异在同行表达，按需打开该字段的来源详情与完整合同。字段草稿支持手动增改删、名称、标识、类型、必填、去重标识、变更检测与说明，真实保存到 Collection，使用 revision、权限、幂等和审计保护。没有草稿时按 key 合并来源输出，每个字段一行，差异保留而非视为统一已发布合同；有草稿时以草稿为主，来源额外字段可按需展开且不自动写入草稿。来源已发布字段只读取不可变活动 RuleVersion，候选规则另行标注。来源合同差异和草稿缺失字段可见，完整输出 Schema 与质量规则可查。字段编辑采用顶部保存操作条，长表编辑时持续可达。未保存标记在分区标签中可见，分区切换保留本地字段草稿；应用内跨页面离开需确认，浏览器刷新/关闭保留原生提醒，保存期间不允许通过离开确认放弃正在提交的内容。后台详情读取失败保留已有数据和本地字段编辑，失败与 revision 冲突不自动覆盖输入，放弃重载使用明确动作。字段编辑和来源证据弹层关闭后恢复触发位置。关联来源把名称和入口网址归组，状态与真实输出字段数并列；合同未知或不可用显示无法确认，不解释为零。草稿不自动应用于新旧来源或运行，不等于字段版本发布。字段版本、模板、AI 建议和来源迁移遵循下述独立确认流程。设置分为系统设置和模型设置两个 URL 同步页签（`?tab=system|models`）。系统设置包含语言、账号、环境及管理员专属的采集策略与用户管理；模型设置保留供应商、模型、默认模型及凭据管理，非管理员只读，读取失败提供重试且不得显示为空配置。桌面下限为 `1024px`，主验收 `1440x900`，补充 `1280x800`、`1132x1028`、`1024x800`；宽表格在自身区域滚动，移动端不在范围内。

## 2. 产品简述

Extrio Web 控制台面向数据接入与运营人员，把一个采集需求和多个授权 Source 从批量接入推进到可审核规则、确定性运行和可追溯 Item。第一版通过 FastAPI、Crawl4AI 与 Crawlee 跑通真实本地纵向闭环，所有对象、状态、ID 和 API 边界与 SSOT 保持一致；MSW 保留为前端隔离开发和合同测试环境。

目标用户需要在同一工作上下文中完成三类判断：Source 是否可访问、候选规则是否可信、Run 产出的 Item 是否满足数据合同。界面重点是状态、证据和下一步动作，不是展示平台功能数量。

## 3. 参考吸收

- `iiwish/caiji`：吸收 Source 工作台、对象上下文连续性、浅色运营界面和明确主动作；不复用其页面级巨型组件、集中 PrototypeContext 或旧领域术语。
- `iiwish/bidly`：吸收样本审核门禁、Action Ladder、紧凑表格和先异常后指标的信息组织；不复用暗色皮肤、静态页面堆叠或 Rule Pack 模型。
- Extrio 使用自己的对象体系：Website 映射为 Source，Rule Pack 映射为 RuleVersion，Execution 映射为 Run，Article/Original 映射为 HarvestItemRevision。

## 4. 最小闭环

```text
选择已有需求或定义新需求，并批量添加精确列表入口
  -> 为每个入口建立独立 Collector
  -> 识别 single 或 list_detail
  -> single：从入口直接提取业务字段
  -> list_detail：遍历列表分页、发现 detail URL、抓取详情并提取字段
  -> LLM 编译 extrio.rule-plan.v1，平台验证并生成 extrio.gather.v1 候选规则与证据
  -> 审核字段、样本、质量与网络边界
  -> 批准并发布 RuleVersion
  -> 立即运行
  -> 查看 accepted/rejected Item 与完整 lineage
```

闭环使用一个演示 Tenant、标讯 CollectionVersion、多个 Source 和一个 RuleReviewer 身份。一个需求通过稳定 `collectionId` 与 `collectionName` 共享 CollectionVersion，每个精确列表入口创建独立 Collector 并返回逐项创建或拒绝结果；同域名的不同业务列表保持独立运行、Checkpoint 与故障边界，站点根目录不作为生产入口。Collector 列表通过所属需求列和可搜索需求筛选器支持跨需求运营与需求内查看；文件夹不承担领域归属。用户操作通过符合 `extrio.control-plane.v1` 的 FastAPI 触发持久化状态转换；探索与 Run 返回 `202 Accepted` Operation，独立 Worker 使用 Crawl4AI 或 Crawlee 执行，页面轮询服务端事实并可在刷新后恢复，不使用静态截图或客户端伪造进度。

Source 输入只接受 HTTP(S)。HTTPS 直接进入正常校验；匿名公共 HTTP 在本地 TenantAdmin 策略允许时显示“风险已标记”并可继续导入。配置 AccessProfile 或凭据的 Source 必须使用 HTTPS。前端提示不得把 HTTP 风险接受描述为主机、DNS、重定向或凭据边界的豁免。

## 5. 信息架构

### 5.1 一级导航

| 路由 | 名称 | 页面任务 |
| --- | --- | --- |
| `/` | 概览 | 判断运行健康、规则覆盖、数据质量与异常趋势 |
| `/collections` | 采集需求 | 搜索和筛选独立需求，进入需求详情 |
| `/collections/new` | 新建需求 | 独立保存需求名称与业务目标 |
| `/collections/:collectionId` | 需求明细 | 编辑元数据、查看与添加来源、归档和恢复、确认删除空需求 |
| `/collectors` | 采集来源 | 创建与继续 Collector 闭环，筛选归档来源并执行独立管理命令 |
| `/runs` | 运行 | 在统一工作区比较采集 Run 与 AI 规则任务 |
| `/ai-runs/:aiRunId` | AI 任务详情 | 实时查看结构化执行阶段、候选结果、模型用量和审计证据 |
| `/items` | 数据 | 查看规范化 Item、Revision 和谱系 |
| `/settings` | 设置 | 配置规则编译模型的供应商、模型与加密凭据 |

概览、采集需求、采集来源、运行、数据和设置构成第一版一级导航。品牌标识与“概览”导航都返回 `/`，未知路由也回到概览，确保用户始终能回到工作区起点。侧栏上部放置核心业务导航，设置固定在底部；侧栏不常驻显示 API 或 Mock 环境提示。顶部栏在一级列表和首页只显示当前一级页面；新建、Collector 详情、Run 详情、AI 任务详情与 Item 详情统一显示图标返回按钮和可返回的“一级页面 / 当前页面”层级导航。Schedule、Sink、漂移中心和完整治理后台不进入第一版一级导航。

`/` 是运营工作台而不是营销首页。页面回答“整体是否健康、趋势如何、哪里需要介入”：使用实际运行成功率、已发布规则覆盖和最新实体质量通过率作为核心指标，用最近运行的数据量与终态组成趋势图，并只保留最多三项异常入口。Run 和 Item 明细仍进入对应一级页面，概览不重复列表、技术 ID、推断式质量分或继续工作入口。健康且最近运行成功的已发布 Collector 不进入待处理队列。`/collectors`、`/runs` 与 `/items` 直接以可换行顶部工具栏和固定列运营列表进入操作，不显示重复的页面标题、说明或概览指标卡。三个对象列表都使用固定列支持高密度横向比较。筛选必须真实生效并写入 URL，不展示仅用于占位的搜索、筛选或设置控件。

三个列表分别回答不同问题：Collector 固定列列表回答 Source 是否可运行、属于哪个需求、当前规则和最近运行是什么、下一步做什么，并从真实最近 Run 计算健康；Collector 顶部工具栏按可用宽度从左到右放置状态筛选、可搜索需求筛选和新建操作，新建按钮位于最右侧，不显示需求标签或布局切换。需求筛选器打开后自动聚焦输入框，按需求名称或合同版本实时过滤选项，选择后更新 URL 并关闭弹层。每行固定对齐 Source 身份、所属需求、状态、活动规则、最近运行和下一步；主体链接进入详情，独立末列菜单提供管理操作；完整需求说明与采集策略进入详情。运行页先以统一线型导航切换“采集运行”和“AI 任务”，不增加侧栏入口；采集 Run 工具栏保留状态筛选、名称或 Run ID 搜索、排序提示和刷新，固定列对齐执行终态、接收与拒绝、范围与停止原因、开始时间与耗时；AI 任务工具栏按进行中、待审核和需处理筛选，固定列对齐 Collector、任务类型、执行状态、候选结果、模型消耗、开始时间与耗时。AI 任务详情以 Source 根 URL 为主标题，以“结果、执行过程、模型调用、证据”组织内容；活动任务自动轮询，执行过程按时间展示 Source 获取、AI 结构分析、详情发现、样本获取、AI 规则编译、确定性验证和结果整理，并给出当前状态、阶段耗时和非敏感结果指标。原始提示词、模型思维过程、Source 正文与响应正文不进入界面。Item 顶部工具栏把 Source、Collector 与质量决定筛选放在左侧，把标题、正文、Collector 或 entity key 搜索放在右侧；固定列列表逐行对齐实体身份、质量决定、变化与 Revision、发布时间、最近采集和 entity key。数据行对 Collector 展示名与 Source host 做语义去重，相同时只显示 host，不同时才并列提供上下文；Source 筛选项只显示 host。Item 列表按 `collectorId + 历史 collectionId + entityKey` 聚合为最新实体，重复 Run observation 进入详情的观察历史，不在实体列表重复占位。

`/settings` 直接进入无重复页面标题的紧凑配置工作面，不设置“供应商配置 / 模型设置”平级 Tabs。顶部工具栏只在左侧展示带星标的唯一默认模型选择，在右侧提供添加供应商，不展示供应商数或可用模型数；正文按供应商分组，组标题展示配置名称、HTTPS API 地址、密钥配置状态、启停状态和模型数量，模型作为该组的子行展示并在当前供应商上下文中添加。供应商和模型的低频编辑、启停与删除操作收纳进各自行末菜单。供应商对话框提供遮罩式 API Key 输入和显隐按钮，新建时必填，编辑时留空保留原值。密钥只随保存请求提交，不进入浏览器存储；API 读取只返回 `credentialConfigured`，不回显密钥。删除供应商会同时删除其模型与加密凭据，停用或删除默认项后自动选择下一个可用模型。设置页在供应商配置上方提供“界面语言”单行控件，可在中文与 English 之间即时切换控制台语言，选择写入本机并在下次访问保持；界面文案通过 i18next 命名空间组织，中文为默认与兜底语言。

Collector 的已受理探索、修复和运行任务使用默认打开的执行日志弹窗展示真实进度、阶段时间、终态和归一化错误。收起不停止任务，轮询不重新打开弹窗；页头保留带状态的查看按钮，新任务默认打开。最近 AI 任务的日志可在刷新后按需查看。操作受理前的请求错误与配置保存错误保留在页面错误条。第三方抓取器堆栈、源码位置和原始浏览器调用日志不进入页面；技术错误码、受控原因标识和 request ID 可用于关联诊断。

规则生成和重新生成使用轻量 Dialog 接收最多 500 字的一次性操作指引，例如希望优先识别的字段或页面结构线索。该指引绑定本次 AiRun 并参与受约束编译；每次提交创建独立记录。界面不提供通用 Chat、消息历史或脱离当前 Collector 的开放式对话入口，因为规则可信度由可执行规则、样本验证和人工审核建立，而不是由对话流畅度建立。

### 5.2 Collector 工作台

Collector 新建与详情以顶部栏建立二级工作流上下文：箭头按钮和一级“采集来源”均返回保留需求筛选的列表，当前页面显示“新建采集来源”或“采集来源详情”；新建正文直接从归属需求表单开始，不重复页面标题、说明和返回链接。详情对象区显示稳定 Source 名称、可返回需求明细的需求归属、当前阶段和唯一主动作；批量导入的“入口 N”顺序不进入主标题，完整入口网址在采集配置首位展示。正文使用“采集配置、运行与结果、规则与证据”三个一级任务视图：`ready_review` 默认进入规则审核，其余状态默认进入采集配置；没有候选或活动规则时不显示规则 Tab。概览集中展示当前状态、入口网址、活动规则、运行范围、最近运行和最多五条最近结果，并以单个紧凑入口关联最近 AI 任务；规则审核先显示发布阻断和审核摘要，再以字段审核/样本数据二级切换完成决定，已发布规则则展示确定性采集流程与验证指标。已发布规则的状态、采集流程、输出字段、验证结果和审核结论直接显示在规则页，不设置额外规则详情 Dialog。采集配置以 URL 为主位展示 Source 定义、定时运行、增量策略、Webhook 推送配置和投递记录；定时运行提供启停、常用频率、自定义五段 Cron、下次运行与禁止重叠说明，规则编辑 Dialog 提供“规则编辑”和“JSON”两个 Tab，完整 GatherSpec 只在“JSON”中按需只读展示；内部版本 ID 与 digest 不作为独立信息项展示，原始 JSON 不允许直接编辑。Webhook 配置提供地址、遮罩式密钥输入、启停、发送测试与版本展示；投递记录逐行展示状态（待投递/投递中/已送达/失败/死信）、最近尝试与错误摘要，死信与失败记录提供重新投递。字段与 Item 证据默认隐藏，用户选择对应对象后通过右侧 Sheet 显示并独立滚动，关闭后返回原触发点。

名称修改只更新对象识别信息。来源采集说明或 Source 入口变化时，界面明确说明调度关闭，当前候选、活动规则和 Checkpoint 清除，历史 RuleVersion 保持可追溯且新 Run 须重新审核发布，并提供“保存并重新生成”主路径。直接规则编辑只操作候选草稿，覆盖列表 Item selector、网页业务字段 selector、分页类型/参数/上限和详情输出字段 selector；`source`、`crawlTime`、`observedAt` 等系统管理字段不进入编辑表单；`detailUrl` 同时作为 Stage 01 输出和 Stage 02 请求输入，不提供含义重复的第二个输入框。字段类型、必填性、错误策略、转换、identity、Item 边界和采集时间来源由 CollectionVersion 固定，只在只读 JSON 中按需查阅，不在编辑表单逐字段重复展示。保存后审核决定清空，服务端使用最近探索样本完成 Schema、详情发现和必填字段验证，再返回新的候选 digest。活动 RuleVersion 不提供编辑入口。

Source 探索和生产运行支持两个确定性计划。`single` 使用必填 list stage 将入口页视为一个采集单元并直接提取字段，不创建 detail stage。`list_detail` 的 Stage 01 执行 `page`、`next_link` 或无分页策略并规范化 detail URL，Stage 02 在同一 Run、RuleVersion、预算和 allowedHosts 边界内抓取详情并进行质量终结。分页是 list stage 内部策略；两阶段不建模为两个独立 Run，也不要求用户手动接力。

公告类 `list_detail` 的数据视图以列表公告为 Item：Stage 01 展示列表标题与详情 URL，Stage 02 展示详情标题、发布时间和公告正文，Run 的 `observedAt` 作为采集时间。Item 列表、Run 结果与 Item 详情不得使用详情正文内部的采购项目、采购单位或预算代替公告级字段。

Collector 工作台必须把“什么时候运行”“怎么翻页”和“采集到哪里”分开展示。定时运行使用独立 Schedule 配置，支持启停、常用频率与自定义五段 Cron，固定 `Asia/Shanghai` 和 `overlapPolicy=forbid`；采集流程确认 next_link 选择器、允许主机和规则硬上限；采集范围面板配置首次窗口、增量回看、连续旧页停止和操作限额，并显示当前 policy version 与 Checkpoint。Collector 与 Run 详情统一使用左对齐紧凑线型任务导航，激活态只使用文字色和底部指示线，不以按钮底色制造额外层级。Run 详情把返回入口放在顶部栏，以 Source 根 URL 和终态作为主信息，将完整入口路径、开始时间、耗时和执行模式收为次级上下文，既避免长 URL 抢占标题层级，也能区分同域名的不同入口；页面不显示“运行记录”眉题。结果、执行过程、范围与增量、质量与证据作为顶部一级任务视图，结果摘要压缩为单行结论与指标带。initial/incremental 模式、窗口下界、窗口外数量、new/updated/unchanged、停止原因和 Checkpoint 前后值进入对应任务视图。

### 5.3 详情层级

- 列表到详情只有一层；精确证据使用 Sheet，不再打开新的嵌套详情页。
- 返回列表必须恢复搜索、筛选和滚动上下文。
- Run 到 Item、Item 到 lineage 使用明确可返回链接。
- Collector 详情主内容按任务视图组织，证据使用按需 Sheet；Run 详情在“质量与证据”视图先展示人可读的可信结论，再以默认收起的技术信息承载 ID、digest 与证明版本，不常驻右侧 evidence rail；Item 详情同样以顶部任务视图组织内容、版本与观察、质量决定、来源与谱系，完整 lineage ID 只在默认收起的技术信息中展示，不常驻右侧证据栏。Collector、Run 与 Item 列表使用带列头的单一表面和行分隔，连续连接线只用于采集阶段与 lineage 等真实关系，不承担普通信息分隔。

## 6. 技术合同

- 包管理：`pnpm`。
- 构建：Vite + React + TypeScript。
- 组件：shadcn/ui 源码组件、Radix primitives、Lucide icons。
- 样式：Tailwind CSS + CSS variables；不引入第二套组件库。
- 路由：React Router。
- 服务端状态：TanStack Query。
- API：浏览器只访问 `/api/v1`；OpenAPI 机器权威为 [`contracts/openapi.yaml`](./contracts/openapi.yaml)，TypeScript 类型由 `pnpm api:generate` 生成。
- 异步命令：探索和 Run 返回 Operation；前端按 `pollAfterMs` 轮询，处理 `succeeded`、`failed`、`cancelled`、`timed_out`，成功后重新读取领域资源。
- API 环境：Vite 隔离开发默认启用 MSW，设置 `VITE_ENABLE_MOCKS=false` 后连接 FastAPI；MSW 与 OpenAPI 使用相同路径、状态码、请求头和响应结构。控制面不可用时前端返回可操作的环境提示，不使用无上下文的通用失败文案。
- Schema：候选规则包含服务端返回的完整 GatherSpec；界面原样显示并由 Draft 2020-12 测试校验。浏览器只提交 OpenAPI 定义的 `CandidateRuleEditInput`，由服务端应用 Override、重算 digest、验证最近样本并返回完整 GatherSpec，浏览器不自行发布或补全机器合同。
- 原型数据：真实中文标讯字段和完整 lineage；不得出现 lorem ipsum、example dashboard 或无业务含义的 KPI。

目录边界：

```text
web/src/
  app/          应用入口、router、providers、shell
  api/          typed client、MSW handlers、fixtures
  components/   跨 feature 组件
  components/ui shadcn/ui 组件
  features/     collectors、review、runs、items、settings、evidence
  lib/          纯函数、格式化、状态语义
```

禁止把全部业务状态放进 AppShell 或单一 Context；页面只通过 typed API hooks 和局部 UI state 协作。

## 7. 设计合同

### 7.1 方向

- Surface：面向专业运营人员的桌面端 operational product surface。
- Design thesis：像检查一条可证明的生产流水线一样完成采集接入，每个决定旁边都有证据。
- Signature move：任务视图先聚焦当前决定，用户选择阻断项、字段、样本、规则、Run 或 Item 时，右侧证据 Sheet 定位到对应固定事实。
- 首页 signature move：把今日、本周、本月经营口径并列放进同一指标带，并让日、周、月只控制采集产出趋势的聚合颗粒度。
- 第一视口必须直接呈现当前 Collector、阶段、阻断项与主动作，不使用营销 hero。

### 7.2 视觉系统

| Token | 值 | 用途 |
| --- | --- | --- |
| `--background` | `#F5F7F8` | 应用底色 |
| `--surface` | `#FFFFFF` | 主工作区 |
| `--surface-subtle` | `#EEF2F3` | 工具栏、选中前背景 |
| `--text` | `#172126` | 主文字 |
| `--text-muted` | `#65737B` | 元数据 |
| `--border` | `#D9E0E3` | 分隔与表格线 |
| `--accent` | `#2557D6` | 主要动作和选中状态 |
| `--teal` | `#087F73` | 探索和证据状态 |
| `--success` | `#16805A` | 通过、已发布 |
| `--warning` | `#B56A09` | 待审核、部分成功 |
| `--danger` | `#C23B3B` | 阻断和失败 |

- 字体使用系统中文 UI 字体栈；正文 `14px/1.6`，紧凑元数据 `12px/1.5`，页标题 `22px/1.35`，letter-spacing 固定为 `0`。
- 间距基数 4px；页面 24–32px，卡片 16–20px，工具栏 8–12px；对象卡片之间保留 12px 间距。
- 卡片圆角不超过 8px；白色表面、克制阴影和多色状态图标建立层级。卡片内部通过字体、留白和浅色状态带组织，不再嵌套新的卡片或依赖连续横线分隔。
- `--border` 只用于卡片外边界、输入控件和真正的表格；阶段连接、lineage 和 diff 可使用具有语义的细线。
- 无渐变、无装饰光球、无大面积深蓝或紫色；状态颜色同时配图标与文本。
- 动画只用于阶段完成、证据 Sheet/rail 切换和异步状态，持续 140–220ms；尊重 reduced motion。

### 7.3 桌面视口

- 支持范围为 `1024px` 及以上桌面视口；移动端和低于 1024px 的窄屏适配不进入设计、实现或验收。
- `1440x900` 是主要设计与视觉 QA 视口，`1024x800` 是最小支持 QA 视口。
- Collector、Run 与 Item 列表在 `1024px` 及以上使用稳定固定列布局；字段审核等高密度比较任务保留表格。Collector 主工作台使用稳定的一级任务导航与全宽内容区，证据 Sheet 在打开时覆盖右侧而不改变主区布局。
- 既有窄屏样式可以在不增加复杂度时保留，但不得作为产品能力、验收结论或后续投入依据。

## 8. 交互与状态

必须实现：

- 从全部需求列表进入时默认定义新需求，从具体需求筛选上下文进入时默认选中并复用该需求的采集意图；用户可切换需求模式后批量添加多个精确列表入口。手动输入每行一个入口；文件导入支持 UTF-8 CSV/TXT、2 MiB 与 1000 行上限，CSV 必须包含 `entryUrl` 或兼容别名，`mode` 省略时为 `exact`，`name` 与 `scopeHint` 可选。重新选择文件替换当前文件条目并保留手动条目；同一 URL 同时出现时，文件内结构化元数据优先。界面固定高度展示文件名、逐行预览、来源行号、采集来源名称、可见范围提示、筛选、HTTP 风险、入口粒度、重复、移除和清除文件操作；文件级错误以警告呈现且不清空最近一次成功解析的预览。创建操作只提交校验通过的 `exact` 项；每个成功入口建立独立 Collector，同批 Collector 返回并共享稳定需求身份。
- Collector 列表首行工具栏集中状态筛选、可按名称或合同版本输入搜索的需求筛选器和右侧新建操作，不显示需求标签或布局切换；筛选写入 URL。固定列列表逐行展示 Source 身份、所属需求、状态、活动规则、最近运行和下一步，详情可返回所属需求明细。
- Run 列表首行工具栏集中状态筛选、按 Collector 名称或 Run ID 搜索、开始时间排序提示与刷新；状态和搜索写入 URL。列表固定对齐身份、终态、接收数、拒绝数、执行范围与停止原因、开始时间与耗时，整行可进入 Run 详情。
- `list_detail` Run 的范围列使用“已抓取/已发现”展示详情页完整度；详情抓取不完整时明确显示部分成功、`detail_fetch_incomplete`、缺失数量和恢复建议，不把已冻结的 accepted Item 误报为完整成功。
- Operation 阶段使用 `queued`、`fetching_list`、`discovering_details`、`fetching_details`、`validating`、`finalizing`、`completed`；状态使用 `queued`、`running` 与四种终态，阶段与指标完全来自 API。排队超过 15 秒时显示 Worker 未领取诊断，明确检查 `extrio-worker` 是否运行以及 Worker 与 API 是否使用同一数据库；该提示不把仍可自动恢复的任务误报为终态失败。
- 候选规则审核根据 `mode` 展示 `single` 单阶段或 `list_detail` 两阶段采集流程；分页策略、停止条件、detail URL 样本和 allowedHosts 证据仅在适用时出现。
- 字段审核使用 `approved`、`risk_accepted`、`excluded`、`pending` 四种明确决定；任何 `pending` 字段阻断发布，发布确认必须逐项汇总决定。
- 样本 accepted/rejected 标记和证据定位；字段、样本、已发布规则、Run 与 Item 分别通过按需 Sheet 显示对应证据，不复用过期选择状态，页面初始状态不显示证据 Sheet。
- 发布确认、权限说明、发布 loading、成功和失败。
- 已发布状态展示 canonical rule digest；新 Run 的“质量与证据”视图直接展示 RuleAttestation、固定策略和结果集冻结状态，attestation ID、digest、SigningKey 与 trust revision 收纳进默认折叠的技术信息，失败不得伪装为已验证。
- Run 的 queued、running、finalizing、succeeded、partially_succeeded、failed、cancelled、timed_out。
- rejected 候选不生成 HarvestItemRevision 或 HarvestObservation；界面显示“未生成”并保留 Run、SourceRevision 与 Artifact 证据，不伪造 Revision 0。Item 质量视图使用 canonical 详情标题与独立列表标题判断一致性，明确显示标题错配原因，不允许比较同一字段后得出虚假的“标题一致”。
- `partially_succeeded` Run 的第一视口必须解释原因、影响范围和下一动作，并允许直接进入拒绝 Item 或返回 Collector 规则工作台。
- Item 顶部工具栏左侧提供 Source、Collector 与质量决定筛选，右侧提供关键词搜索，并将状态写入 URL；固定列列表按 `collectorId + 历史 collectionId + entityKey` 展示最新实体，逐行显示公告标题、质量决定、变化、Revision、观察次数、发布时间、最近采集时间和 entity key。Item 详情顶部显示公告标题、终态、Source、发布时间和 Revision，并通过“数据内容、版本与观察、质量决定、来源与谱系”四个线型任务视图分别承载正文、差异和历史、质量结论、可操作来源入口与完整 lineage；技术 ID 默认收起。
- 导航、按钮、Tab、Sheet、Dialog 的 hover、focus、active、disabled 和 keyboard path。
- 设置页支持多个供应商、每个供应商的多个模型、供应商和模型启停、级联删除与唯一默认模型快速切换；密钥未解析状态使用文字和图标共同表达，API 与浏览器均不出现密钥明文。

## 9. 非目标

- 本地闭环由 Crawl4AI 按固定导航条件和异步内容沉降时长固化入口、列表和详情样本，当前默认模型在接入期编译受约束 RulePlan，服务端验证 selector、分页、字段、身份与样本命中后生成候选 GatherSpec 并记录模型谱系；已发布规则的生产 Run 使用同一浏览器 snapshot 时点和确定性运行时，不读取模型设置或调用 LLM。开发持久化使用 SQLite 与本地 sampled Artifact。
- 实现首次本地管理员设置、最少 8 个字符的密码输入约束、登录与退出；多 Tenant 切换、MFA、四眼审批和审计导出不在公开 Alpha 范围。
- 不实现独立 Schedule 管理页、Kafka Sink、漂移恢复和 Artifact 下载；Collector 详情内提供可执行的定时计划配置、Webhook Sink 配置、投递记录与重新投递（v0.3 交付），Item 列表工具栏提供携带当前筛选的 CSV/JSONL 数据导出。
- 不把 mock 状态或演示签名描述为生产证据。

### 概览看板时间范围

概览看板的指标带同时显示今日采集、本周运行成功率、本月有效数据和当前规则覆盖。日、周、月分段控制只位于“采集产出趋势”图内，默认按日显示最近 14 天，按周显示最近 12 周，按月显示最近 12 个月；柱形以接收和拒绝数据堆叠。右侧运行质量面板与趋势范围联动，展示成功率、成功/部分成功/失败分布和数据通过率；需要关注面板只保留最多三项人工动作。经营指标通过 `GET /api/v1/overview?timezone=<IANA>` 在服务端全量聚合，不受列表 200 条上限影响。按浏览器时区的自然日、周一和自然月划分半开区间，运行按持久化创建时间归桶；成功率分母仅包含已终结运行，取消/超时计失败，活动运行单列。本月实体先按来源与 entity key 取最新观测，再按该行 UTC 入库时间判断月份；历史 observedAt 展示字符串不用于时区推断。页面提供快照时间和刷新，失败显示无法确认而不是零或健康。需要关注区域使用来源及最近运行列表，只展示最多三项，不作为全量异常统计。

## 10. 验收

1. 用户从全部需求列表进入时默认新建需求，从具体需求筛选上下文进入时默认复用该需求并只补充采集入口 URL；两种模式可切换，系统逐项返回创建或拒绝结果，同批成功 Collector 共享稳定需求身份，任一合法 Source 可继续完成探索、审核、发布和立即运行。
2. `single` 原型明确展示直接采集与质量终结；`list_detail` 原型明确展示列表分页、detail URL 发现、详情抓取和质量终结。Run 完成后至少展示 3 个 accepted Item、1 个 rejected 候选、质量统计和一条可展开的完整 lineage。
3. 任一阶段的当前状态、阻断原因、下一步动作和证据在三秒内可识别。
4. `/`、`/collections`、`/collectors`、`/runs`、`/items`、`/settings` 可直接访问，品牌标识可从任意页面返回 `/`；主页待处理、运行和数据 Tabs 可通过鼠标与键盘切换。Collector、Run 与 Item 使用固定列运营列表；Collector 列表的状态和需求、Run 的状态和搜索、Item 的 Source、Collector、质量决定和搜索写入 URL，三个详情使用主卡与证据卡组，详情 URL 在刷新后恢复服务端状态。设置页可分别保存多个供应商与模型、切换唯一默认模型，并明确显示每个供应商的密钥解析状态。
5. Collector、Run、RuleVersion、RuleAttestation 与 Item lineage 使用同一冻结版本；新 Run 的完整性证据必须来自 API 固定事实，演示 Source、候选字段、Item 内容和 Source URL 必须属于同一场景。
6. 桌面 `1440x900` 与 `1280x800` 无文字溢出、布局重叠或不可达主操作；低于 `1024px` 的视口不属于验收范围。
7. Collector 详情的采集来源定义与规则工作区在两种支持视口均可扫描和操作；需求归属通过独立确认流程调整，固定数据合同只读；名称修改保留活动规则状态，来源采集说明或入口修改关闭调度并清除后续执行依据，提供保存后重新生成路径；直接规则编辑产生新候选 digest、清空旧审核决定并显示最近样本验证结果，已发布 RuleVersion 始终只读。
8. `pnpm api:generate`、`pnpm build`、TypeScript、lint、OpenAPI/异步合同测试和 GatherSpec Schema 测试通过。
9. 前端不包含 secret、真实签名私钥、内部对象存储 URL 或把客户端 tenantId 当作权限依据的逻辑。
