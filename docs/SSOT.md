# Extrio 单一事实来源

## 1.0 交付范围

1.0 的交付范围为单组织自托管稳定版，面向一个组织内的数据运营团队，保留本地账号角色、SQLite 评估和 PostgreSQL 部署路径。多租户、SSO/MFA、分布式高可用和移动端不属于本次交付范围。全站页面的内容组织、桌面布局、操作流程和状态反馈属于 1.0 的体验验收范围，不以功能测试通过或单纯调整样式代替。具体页面方案需以真实界面走查和用户复核为依据，沿用唯一正式前端。

1.0 的功能、AC/NFR、部署依赖和退出条件以[单组织自托管验收范围](planning/v1.0-scope-matrix.md)为版本适用合同。功能实现、工程验证、页面设计签收和生产目标达成分别记录，不将范围确认视为已实现或已验收。

## 运营状态与处理入口

首页与来源列表共享当前来源待处理分类，纳入首次待运行、待审核、待生成、待完成迁移、活动规则缺失、最近运行不可用及最近终态异常。归档来源和实际执行中的来源不计为待处理；历史异常不替代最新运行。字段目标尚未开始迁移的未对齐来源在需求详情独立呈现，不从首页待处理数量推断全部需求已达成。

需求详情默认字段分区即可看到目标版本、活动来源未对齐数量及版本未知数量；归档来源不计活动对齐，未知不显示已对齐。查看对齐只切换来源分区，保留筛选和字段草稿，不发起迁移。来源概览独立显示规则资格、最近结果与持续更新状态，展示真实调度开关、频率、时区及下次运行，未开启时明确仅手动、不自动更新。

运行成功不代表采集范围完整，达到页数上限的正常终止保留结果与范围未确认提示。部分成功分开呈现质量拒绝和未获取页面；本次拒绝筛选保存在 URL，展示该运行返回的拒绝记录，记录不全时明确已加载数量。获取与访问问题先进入执行诊断，字段质量或明确结构问题可查看规则证据；任何导航均不自动重跑、修订或发布规则。

## 体验设计评审

模型设置使用默认模型工具栏与供应商分组面板，供应商身份、凭据状态和模型行分层展示，复用 DetailPanel。编辑弹窗统一尺寸，保存与删除失败在弹窗内反馈；密钥隐藏、权限与删除确认保持有效，不模拟连通性测试。

系统设置以统一白色面板呈现偏好与账户、实例运行状态、采集策略和用户管理；复用 DetailPanel，保持紧凑指标与稳定用户列宽。权限、安全策略及账户操作保护沿用既有行为，模型分区独立验收。

新建来源使用来源列表上的宽弹窗，表单内部滚动、操作栏吸底；保留需求归属、批量 URL 校验、文件导入和部分成功结果。格式说明按需展开，未保存关闭沿用离开确认，提交中禁止关闭；单条成功进入来源详情，批量导入保留结果页。

新建需求使用需求列表上的创建弹窗，仅填写需求名称和采集目标；底部操作为取消与创建需求。弹窗最大宽度 640px，直接访问 /collections/new 也显示列表与弹窗。点击遮罩不关闭，提交中阻止关闭；保留权限、校验、失败重试及幂等保护，成功后进入需求明细。编辑弹窗仍使用保存需求语义。

数据明细复用 DetailPanel 和运行详情导航样式。正文区将正文/HTML 切换集中在面板标题栏，摘要采用紧凑事实区；版本观察、质量决定、来源谱系保持独立分区，来源链接采用无嵌套卡片的信息行。长标题、URL 和差异内容支持换行；HTML 仅以惰性文本或转义源码显示，不执行采集内容。

AI 任务详情与采集运行复用 DetailPanel 和运行详情样式，统一结果、执行过程、模型调用、证据四个分区。结果摘要集中展示调用量及验证计数，产出与审核单独呈现；过程页保留预算摘要和阶段记录，逐页读取数据置于证据页。模型列允许长名称换行，失败和运行中的尝试使用对应图标。技术标识保持按需展开，不展示敏感提示词或响应正文。

产品体验成熟化的 P0/P1 技术验收通过。P2 的来源 URL 配置子项已获用户确认并实现，其余设计样板处于用户评审状态，见 [P2 设计合同](design/product-maturity-p2/design.md)；需求内数据查询、样本证据工作区和分组处置目标不作为当前已实现能力，其余 P3 实现须经对应页面方案确认。

来源详情以 URL 配置为主任务：普通状态默认「采集配置」，待审核默认「规则审核」，显式 section 深链接优先。采集配置首位展示完整入口 URL、复制/打开/编辑，其后是采集说明与需求归属、定时运行、采集范围；数据合同和推送投递按需展开。「运行与结果」承载既有运行摘要；「规则与证据」承载审核、验证和直接展示的规则工作区。URL/意图修改沿用现有保存确认、规则失效、关闭调度、权限与并发保护，不自动执行采集。实现与验证见 [来源 URL 工作区](planning/source-url-workspace.md)。 三个分区统一使用白色、浅边框、8px 圆角的工作面板和 16px 分区间距；规则工作区不提供折叠入口。 页头仅保留状态主操作、执行日志和管理菜单；AI 修复位于规则操作区，证据包导出位于分区底部。

采集运行详情保持结果、执行过程、范围与增量、质量与证据四个分区。运行面板与来源规则工作区共享 DetailPanel，统一白底浅边框和 8px 圆角。执行指标及阶段记录使用留白分组；质量与证据不嵌套卡片，技术标识按需展开。终止原因、权限、取消确认状态、拒绝结果筛选和证据真实性沿用领域行为。

需求、来源、采集运行、AI 任务和数据列表共享 ListWorkspace、ListPagination 与 useListQuery。工具栏、数量、错误提示和底部分页栏固定；列表填满窗口剩余高度并独立滚动，表头吸顶，宽列仅在列表区域横滚，详情页保持独立的文档滚动模式。底栏显示当前行范围、筛选总行数、每页行数、当前页、总页数及首页/上一页/下一页/末页和跳页控件；每页可选 20/50/100/200 行，默认 50。页码与条件写入 URL，筛选、排序、视图和页大小变化回到首页，换页替换行并重置纵向位置，刷新与详情返回保留页码，超界页回落到末页。数量来自服务端全量统计，不以当前页或前 200 条推算；未知数量不显示零，刷新失败保留旧数据并标记未刷新。需求列表采用紧凑行、单行说明摘要和按需可读的完整名称/合同。运行与 AI 历史使用数据库计数与分页；需求和来源复用领域汇总模型在服务端筛选分页，来源附带当前页各来源的精确最近运行。实现合同见 [统一列表分页](planning/unified-list-pagination.md)。

需求明细以名称和采集目标为首屏主体，来源发布覆盖与当前生效字段版本集中呈现，版本对齐提示独立于来源规则发布状态。字段工具菜单统一承载模板、AI 建议与来源字段导入，版本历史为具名图标入口，编辑和发布操作保持可见；关联来源表按来源、状态、版本对齐、输出字段数和管理操作设置五列。详情保持文档滚动，完整目标可展开，权限、发布确认、迁移确认与未保存草稿保护保留。逐页优化范围及实现合同见 [详情页逐页打磨](planning/detail-page-polish.md)。

需求字段提示区分“尚未应用最新字段要求”与“版本无法确认”，已知未应用时说明来源仍按原规则采集、不会自动更新。来源覆盖只表示包含字段的来源数量，不证明约束或版本一致。来源详情的入口 URL 使用独立工具区，来源说明与需求归属并列，定时运行与采集范围在受支持桌面尺寸下并排展示；数据合同和投递记录保持按需展开。

## 自托管可靠性

运行正常达到配置页数上限且没有拒绝记录时记为成功，保留 max_pages 停止原因，结果页明确数据已保存；不显示等待处理或修订规则入口。有拒绝记录或抓取异常时保留异常处理状态。按页数完成不等于完整遍历时间范围，因此该停止原因不推进增量水位，避免跳过尚未遍历的数据。

列表发现与运行共用下一页地址解析：支持普通 href 和受限的静态 location.href 字符串赋值（可包装 encodeURI），不执行页面脚本。可识别的下一页必须通过发现阶段验证，不能以关闭分页或错误的查询参数分页规避；任务证据以具体分页错误码和字段路径呈现失败原因。

API 存活与实例可工作分开表达：`/healthz` 只报告存活，`/readyz` 检查同库 Worker 心跳、代码/合同/共享配置一致性及已使用密钥状态；设置的系统页提供真实 Worker、队列和恢复原因，不以读取失败显示健康。运行页按持久化 Operation 轮询，工程师或管理员可取消；运行中先显示取消已请求，只有持久终态才显示停止。失败原因按网络边界、访问、结构、预算和实例问题给出操作提示，不静默绕过授权或发布修复规则。

Run、Items、Checkpoint、Operation、Webhook 入队和 job 完成在有效租约事务内提交；过期 Worker 不得提交结果或错误，取消/超时不推进 Checkpoint。Webhook 使用稳定 Delivery ID、独立租约和有限重试；人工恢复保留历史，不因地址版本变化静默改投。单组织认证保护首次/最后管理员、角色边界与会话撤销，规则证明使用实际发布主体，不宣称四眼审批。

本地证据按 available/missing/expired/corrupt 等真实状态展示；sampled/metadata_only 不启用等价回放，失败终态不自动显示结果集已冻结。Worker 定期清理到期 raw，保留 manifest 摘要。全量离线备份包括 SQLite/PG、Artifact、当前签名 key 和完整凭据 keyring，恢复只接受空目标；缺失密钥和半恢复不得通过自动生成密钥或清除保护标记变成成功。密钥轮换保留可解密代际和历史公钥。

支持范围、HTTP/浏览器限制、双数据库恢复、安装/readiness、API/MCP 交接与停止方法见[自托管运维手册](self-hosted-operations.md)。固定来源样本和短期基准不等于外站/真实模型验收、月度 SLA 或 RPO/RTO 达标。本次发布按用户 2026-09-15 的决定豁免 72 小时观测门槛，不声明持续观测通过；用户设计与产品签收独立。

API 与 Worker 的初始化按数据库串行执行：SQLite 同机文件锁覆盖首次 WAL 设置、迁移和补齐；PostgreSQL 会话锁覆盖迁移和补齐。并发启动不得重复执行迁移或使 Worker 因建表冲突退出。

审核字段样本来自实际提取结果，验证样本计数使用真实预览记录；发布确认展示当前登录主体。需求字段与活动版本一致时标识为已发布字段，未保存编辑仍作为草稿。投递记录在配置面板可见期间每五秒刷新，空列表也能发现后台新交付；页面失焦时不持续后台轮询。

## 自适应网页证据

内部详情 URL 交接通过列表记录与详情样本核验，不要求内部 detailUrl 出现在冻结的业务输出中。同一证据下连续三次纠错未解决任何已有验证问题时停止；仅改写提案说明或无效 selector 不计作验证进展。

来源规则生成和修复采用有界的“DOM 结构索引 → 按需读取 → 完整样本验证”协议。模型只能展开或读取本次已抓取的 HTML/JSON 快照，不能请求任意 URL、执行脚本或修改输出合同。目录与超长节点可分页，片段包含范围、快照摘要、祖先上下文和后续游标；提取与质量验证使用完整快照，不把片段当作完整正文。

每次新执行共享最多 16 次模型调用、120000 输入 token、16000 输出 token 和 240 秒预算，包括补读、无效提案、重试和恢复；历史任务恢复不提高原调用上限。发现阶段最多消耗 12 次，保留 4 次供后续编译与校验纠错。每轮最多 6 个读取请求，按实际上下文余量分配，每节点最多 6000 字符、每次展开最多 16 个子节点；连续 3 次无新证据或新提案则停止。调用前预留预算，存在供应商 usage 时校准，缺失时按预留计入；取消、租约失效或预算不足不能提交未验证候选。字段缺失、标题不一致、URL 交接与实体冲突形成包含字段路径和具体原因的结构化反馈，在剩余预算内补读并重新验证；失败保留原候选，不自动接受风险、排除字段或发布。

模型设置支持可选的上下文、输入、输出与推理预留上限。旧配置使用明确标记的保守默认值，未知模型采用 UTF-8 保守估算；可匹配的模型采用本地 tokenizer 加余量。8K/16K/32K/128K 是预算测试档位，不是对具体供应商兼容性的承诺。AI 任务的执行过程与证据页展示阶段、调用和 token 预算、节点读取量、验证状态与停止原因；读取量不等于语义覆盖率或识别准确率。生产采集继续只执行已发布规则，不调用模型。

## 核心操作上下文

来源详情的已受理探索、修复与运行通过默认打开的执行日志弹窗呈现 Operation 进度、阶段时间、终态及受控诊断。收起不取消任务，轮询不重新打开；页头保留查看按钮，新任务默认打开，最近 AI 日志可在刷新后按需查看。明确的浏览器导航超时最多重试一次，共享既有网络预算与访问边界；无 HTTP 响应不构造 HTTP 0 状态。

规则审核的字段警告逐项显示字段标识、验证问题与“修复此字段 / 查看证据”操作，并说明样本缺失不等于来源没有内容。修复入口自动带入当前字段与警告作为本次说明，经确认后调用既有 AI 修复任务，保留输出合同与人工发布门。工程师/管理员以外角色、归档来源、活动任务与待迁移状态不能发起修复。取消不提交；请求失败保留修复说明供重试，不自动排除字段或接受风险。可选字段排除后不再输出；接受风险不会补齐缺失值，界面不承诺修复必然成功。

来源、运行、AI 任务和数据详情通过安全的站内 returnTo 保留入口筛选及 section 分区，返回不丢失来源页面的上下文。搜索可独立清除，刷新保留筛选；首次读取失败提供重试，不显示伪空列表，后台错误保留已读取数据。运行时间使用持久化 ISO 时间，不把历史运行显示为“刚刚”。正文中的 HTML 仅以惰性解析后的纯文本阅读或转义源码显示，不挂载源站脚本、图片和 iframe。来源概览区分已发布规则与最近异常运行；只读角色不能触发来源执行、定义/规则/策略修改或 Webhook 发送。接入表单的录入和导入预览具有离开确认，刷新/关闭使用原生未保存提醒；提交失败保留输入，成功创建可进入详情。设置弹层关闭后恢复原操作按钮焦点，退出失败保留会话并可重试。

## 来源生命周期与所属需求

来源支持需求内新增、基本信息编辑、保留历史的来源删除、归档恢复和独立的所属需求调整。工程师与管理员可执行管理命令，审核发布沿用现有角色边界。来源列表与详情、需求关联来源表提供统一管理菜单；列表默认仅显示活动来源，已归档筛选与搜索、需求条件一起写入 URL。归档来源在需求详情仍可追溯，但不计入可执行来源覆盖。

生命周期 `active|archived` 与规则探索/发布状态分离。归档原子关闭调度，禁止探索、修复、发布、运行与执行配置修改；恢复不启用调度、不启动任务或重发历史投递。实际排队、已领取、运行中的任务及未完成字段迁移阻断归档、删除、定义编辑和归属调整。调度领取后创建运行前再次验证来源状态。

删除来源不可恢复，但不删除规则、运行、数据、操作、AI 任务、证据、策略、调度历史、Webhook、投递或历史归属。已完成的历史不阻断删除；排队或执行中的任务、未结束运行和未完成迁移阻断。删除原子关闭调度、写入不可恢复墓碑，将来源从列表、需求关联与来源统计排除，并释放 URL。重新添加同一 URL 创建独立身份，不继承旧规则、数据、调度或 Webhook。归档可恢复且保留 URL 占用。

删除弹窗显示最新名称、URL、保留的历史数量及操作影响；只有最新预览允许删除时才显示名称确认输入，阻断时显示实际原因与处理方式。重新加载预览后重新输入名称确认。历史运行、AI 任务和数据标记“来源已删除”，保留内容与证据访问，不提供已删除来源的跳转、审核、修复或执行入口。已有投递仍按原合同处理，不因来源删除重发或取消。

基本信息编辑使用 managementRevision 乐观锁；仅改名保留规则，修改采集意图或规范化入口则关闭调度，清除候选、活动规则与 Checkpoint，后续需重新探索、审核发布。所属需求通过独立的目标选择、字段差异和影响预览确认，不混入基本信息编辑。目标必须是不同的活动需求，确认固定目标版本、revision 和全部差异；来源采用目标意图，历史规则、运行、数据与投递 payload 不重写，Webhook 配置保留。

Run、AI 任务、Operation 和 Item 的历史需求归属来自独立不可变记录，以 `collectionAttribution` 返回，不能用当前来源归属解释旧记录。已有历史的来源调整归属后停止调度并撤销旧规则的后续执行资格，新运行须重新探索、审核发布。无法可靠还原历史归属时列出具体记录并阻断调整，不猜测回填。列表、详情和两侧需求缓存同步刷新；提交中禁止重复操作和关闭，失败保留输入并复用幂等键，预览过期明确重载，删除从详情返回原筛选列表。

## 数据查询与导出

数据页使用 `GET /items?view=entities&page=N&limit=50`，服务端按 `collectorId + 历史 collectionId + entityKey` 选择最新观测后应用筛选，返回匹配实体总数、全局筛选选项和 `pagination` 页码元数据。页面采用服务端 LIMIT/OFFSET 换页，不累计前页；默认每页 50 行，可选 20/50/100/200 行。固定底栏由通用 ListPagination 展示当前行范围、总行数、每页行数、当前页与总页数、首页/上一页/下一页/末页及页码输入跳转。`page` 和 `pageSize` 写入 URL，详情返回保留页码；筛选或页大小变化回到首页，刷新保留当前页，换页重置列表纵向位置。超界页回落末页，空结果为第 1/1 页、0 行；读取失败显示错误与重试，不把前页内容冒充目标页，缺失元数据不虚构行数与页数。`q` 对标题、正文、来源名称和 entity key 做字面子串搜索，`sourceHost`、`collectorId`、`decision` 为精确筛选。CSV/JSONL 导出复用相同实体视图和全部筛选，覆盖匹配全集而非当前页，超出上限明确拒绝。默认 API 提供观测视图，保留 cursor/limit 兼容；page 与 cursor 互斥，entityKey 为精确匹配。分页为实时视图，不承诺跨请求快照或深 OFFSET 恒定耗时。桌面工具栏可收缩，分页和导出在最小支持视口可达，宽表格仅在自身区域滚动。

字段变更比较保留 JSON 类型，`null`、`0`、`false`、空字符串、空数组和空对象不合并为同一值；对象键顺序和数值等价表示不制造 Revision。有效变化追加 Revision 并进入已配置 Sink 的交付队列，不重写历史结果。

## 字段版本与受控迁移

字段草稿、不可变 CollectionVersion 和来源活动 RuleVersion 是三个独立状态。工程师或管理员可编辑草稿、应用模板和请求字段建议；审核者或管理员可发布字段版本、审核并启动或放弃来源迁移。字段发布冻结字段列表、JSON Schema、去重标识、变更检测字段及完整语义摘要；至少包含一个必填去重字段和一个变更检测字段。发布使用预览时的 revision、幂等键和原子审计，历史版本只读。有来源、已发布版本或字段建议审计历史的需求禁止物理删除，可归档。

新来源在创建时绑定需求活动字段版本，后续修改草稿或发布版本不会修改该绑定。尚无已发布版本的需求保留旧静态合同兼容路径，不将草稿视为已发布合同。固定版本的编译、预览、人工发布和运行使用同一不可变合同；缺失、跨需求或不匹配的版本不能静默回退。规则修复保留固定合同，运行不能由模型或可变草稿扩展业务字段。

来源迁移计划固定目标版本、差异及摘要，逐项确认所有字段增删改；运行、编译或审核操作进行中时禁止切换。确认迁移仅创建待重编译状态，当前绑定和活动规则保留；候选须通过重新生成、预览、审核和人工发布，发布事务才切换版本。失败显示真实原因，可重试或明确放弃。放弃不修改活动规则；来源定义未修改时恢复迁移前候选与审核状态，定义已修改时清除不适用候选并要求重新生成。旧版本和历史运行不重写。

内置公共公告、产品目录、活动日历模板使用稳定版本标识，预览展示字段差异，确认后替换保存的草稿而不发布。AI 字段建议复用默认模型供应商及网关，通过独立持久任务队列由 Worker 执行，不伪装为来源 AI Run。模型输入仅为需求名称、最多 4000 字目标及最多 50 个草稿字段的受限摘要，不发送网页样本或凭据。每需求最多一个活动任务、每小时最多五次请求；模型输出须通过 1–32 个字段的结构和语义校验。任务有 120 秒租约、最多三次领取及尝试 fencing，模型调用有超时与成功/失败、usage、摘要审计。

字段建议入口保留最近 20 个任务及排队、生成、失败、可选择、已应用状态，刷新恢复持久结果。建议完成不自动修改草稿，用户逐字段选择后按 key 合并；过期 revision 拒绝应用，失败保留选择及本地输入。未保存本地字段编辑时禁止模板和建议应用入口。字段版本、模板、建议与迁移界面共用正式前端，中英文桌面验收范围一致。

## 单前端实现边界

需求详情的“添加来源”在当前页面打开弹窗，固定提交当前 Collection ID，不提供切换或新建需求选项。支持逐行输入多个精确列表页入口，校验无效与重复地址；创建成功后刷新需求详情、需求列表和来源列表，并定位“关联来源”。部分失败明确显示逐项原因，仅保留失败入口供重试；请求失败保留输入，同一请求重试复用幂等键，提交期间禁止关闭，放弃输入需确认。已有来源不按需求名称自动迁移，重复地址由服务端明确拒绝；该入口不自动探索或发布来源。文件批量导入保留在采集来源工作面。

Extrio 只有一套正式前端：`web/index.html` → `src/main.tsx` → `app/router.tsx`，共享 AppShell、AuthGate、QueryClient 与 API 客户端。一级导航为概览、采集需求、采集来源、运行、数据、设置。需求列表读取独立持久化的 Collection，点击进入 `/collections/:collectionId` 明细，展示完整目标、字段要求、来源执行合同与关联来源；明细支持添加来源，来源归属链接返回需求明细，需求列表的搜索、状态筛选和更新时间排序通过 URL 保留，详情返回不丢失列表上下文。需求列表把名称与两行目标摘要放在同一业务单元，按来源发布覆盖、最近更新时间和合同引用进行比较；使用中、已归档和全部筛选显示各自数量，清除搜索只清除关键词，刷新保留当前条件。初始加载与失败不显示零需求，空列表、当前状态为空和搜索无匹配分别提供反馈。合同引用与来源发布覆盖不代表统一字段版本已冻结、调度开启或运行健康。需求支持独立新建、名称与业务目标编辑、空需求删除、归档和恢复；工程师与管理员可操作，其他角色只读。有关联来源的需求禁止删除；归档禁止编辑需求与添加来源，不停止已有来源、定时采集或运行，不删除历史数据。编辑使用 revision 冲突校验，不覆盖已有来源采集说明及不可变规则；新来源使用当前业务目标。模型、凭据、审核、运行与数据保留现有后端能力。旧 `experience.html` 地址仅用于兼容跳转，不提供独立应用或模拟业务数据。

需求详情以“采集字段 / 关联来源”组织工作面，字段仅展示一次。头部集中需求身份、使用/归档状态、来源发布覆盖与更新时间，长目标或多段目标支持摘要与全文展开。当前分区通过 section=sources 写入 URL，采集字段为默认分区；刷新恢复分区，返回列表保留 q/status/sort 且不携带详情 section。字段名称、技术标识和业务说明归入同一列，编辑操作列固定宽度；来源覆盖和约束差异在同行表达，按需打开该字段的来源详情与完整合同。字段草稿支持手动增改删、名称、标识、类型、必填、去重标识、变更检测与说明，真实保存到 Collection，使用 revision、权限、幂等和审计保护。没有草稿时按 key 合并来源输出，每个字段一行，差异保留而非视为统一已发布合同；有草稿时以草稿为主，来源额外字段可按需展开且不自动写入草稿。来源已发布字段只读取不可变活动 RuleVersion，候选规则另行标注。来源合同差异和草稿缺失字段可见，完整输出 Schema 与质量规则可查。字段编辑采用顶部保存操作条，长表编辑时持续可达。未保存标记在分区标签中可见，分区切换保留本地字段草稿；应用内跨页面离开需确认，浏览器刷新/关闭保留原生提醒，保存期间不允许通过离开确认放弃正在提交的内容。后台详情读取失败保留已有数据和本地字段编辑，失败与 revision 冲突不自动覆盖输入，放弃重载使用明确动作。字段编辑和来源证据弹层关闭后恢复触发位置。关联来源把名称和入口网址归组，状态与真实输出字段数并列；合同未知或不可用显示无法确认，不解释为零。草稿不自动应用于新旧来源或运行，不等于字段版本发布。字段版本、模板、AI 建议和来源迁移遵循下述独立确认流程。设置分为系统设置和模型设置两个 URL 同步页签（`?tab=system|models`）。系统设置包含语言、账号、环境及管理员专属的采集策略与用户管理；模型设置保留供应商、模型、默认模型及凭据管理，非管理员只读，读取失败提供重试且不得显示为空配置。桌面下限为 `1024px`，主验收 `1440x900`，补充 `1280x800`、`1132x1028`、`1024x800`；宽表格在自身区域滚动，移动端不在范围内。

设计见 [核心体验重构方案](core-experience-redesign.md)，实现与验收见 [前端说明](experience-prototype.md)。

1. 本文件中的产品边界和 `INV-*` 不变量优先于其他文档。

## 3. 产品定义

Extrio 是面向需要持续采集公开或已授权网页、并要求每条数据可验证的数据运营团队的自托管可信网页数据管线。首要场景是招投标、监管公告和公共通知等列表/详情型来源。

用户定义“要采什么”以及数据质量要求，平台把意图固化为版本化的数据合同；编译阶段结合 Source、CollectionVersion 与受控的 CollectorOverride 生成不可变 RuleVersion；运行阶段只执行已发布规则，不调用 LLM，也不隐式修改规则。每个结果必须能追溯到确切的规则、数据合同、运行记录和证据。

Extrio 的核心价值是：

1. 缩短合规 Source 从意图到首批有效数据的时间。
2. 将站点采集知识从一次性代码转化为可治理规则。
3. 让运行、数据质量、异常和回放具备统一证据链。
4. 在 Source 变化时快速发现漂移，并通过新规则版本恢复。

Extrio 的产品边界是“AI 辅助接入、人工审核发布、确定性持续运行”，不是通用爬虫工具箱、网页聊天机器人或自主 Agent 平台。可扩展性来自 LLM 在接入期理解网页并编译受约束规则，而不是运行期自由生成代码。平台不提供验证码破解、访问控制绕过、代理售卖或任意代码执行能力。对外唯一产品名为 `Extrio`；`RulePlan`、`GatherSpec`、`Collector` 与 `RuleVersion` 是内部领域术语。

14. 一级“设置”页面按供应商分组同屏管理模型，不把存在归属关系的两个对象拆成平级 Tab。顶部左侧只提供唯一默认模型选择，右侧提供添加供应商，不展示缺少决策价值的供应商或可用模型计数；每个供应商组展示连接、密钥与启停状态，并在组内添加、启停、编辑或删除模型。用户在供应商对话框中直接录入 API Key；浏览器只在保存请求中短暂提交，不写入本地存储，控制面使用独立主密钥加密落库，所有读取响应只返回 `credentialConfigured`。供应商可拥有零到多个模型；模型能力只属于探索与候选规则编译边界，不改变运行期禁用 LLM 的不变量。
15. Source 首次抓取失败必须归一为稳定的 `SOURCE_UNREACHABLE`，向用户说明域名、连接失败类别和检查动作；第三方抓取库的堆栈、源码行号和内部路径只允许进入受控日志，不进入操作错误正文。
16. Run 详情的返回操作位于顶部栏，不在正文重复展示。首屏以 Source 根 URL 作为主标题，以完整入口的路径、终态、开始时间、耗时和执行模式作为次级上下文；同域名下的不同入口仍可通过路径区分。页面不显示“运行记录”等无信息眉题，也不把 Run ID 作为主信息；结果、执行过程、范围与增量、质量与证据使用与 Collector 详情一致的左对齐紧凑线型任务导航。结果摘要以单行结论和指标带呈现接收、拒绝、变化与耗时，不重复堆叠统计卡。执行证据先表达规则证明、固定范围、结果集冻结和 Artifact 保留方式等人可理解的结论，对象 ID、版本 ID、digest、attestation 与 SigningKey 收纳在默认折叠的技术信息中，页面不常驻右侧 evidence rail。
17. Item 详情的返回操作位于顶部栏，首屏以公告标题、质量终态、Source 身份、发布时间与 Revision 建立对象上下文。“数据内容、版本与观察、质量决定、来源与谱系”使用与 Collector、Run 详情一致的左对齐紧凑线型任务导航。数据内容先展示规范化字段与正文；版本变化与观察历史合并为同一任务视图；质量决定呈现可读结论和拒绝原因；来源与谱系先提供 Collector、详情来源和最近 Run 的可操作入口，Entity key 与完整 lineage ID 收纳在默认折叠的技术信息中。页面不常驻右侧 evidence rail，也不在主标题下展示 Entity key。

### 5.2 不在当前范围

- 验证码破解、登录绕过、付费墙绕过或违反 Source 条款的采集能力。
- 用户提交并在 Worker 中执行 Python、JavaScript 或其他任意代码。
- 多区域主动主动部署、复杂财务计费、代理交易市场。
- 端到端 exactly-once 承诺。
- 自动删除 Source 中已经消失的实体；当前版本只输出显式识别的删除或撤销事件。
- 无人审核的生产规则发布；自动发布只能在后续版本通过独立风险决策引入。
- 通用 cursor、无限滚动、任意增量表达式和双向回填；当前版本的增量只覆盖具有列表发布时间、时间降序和 `next_link` 的 Source。

## 6. 技术基线

- Python FastAPI 控制面是租户、领域对象、权限、发布、调度、审计和交付状态的唯一写入入口；生产长任务不在 API 请求进程内执行。
- Python 编译服务使用 Crawl4AI 获取完成导航并经过固定沉降时长的渲染 Source 样本；当前默认模型先编译列表发现计划，再结合详情样本编译受约束 `extrio.rule-plan.v1`。服务端对 selector、分页、字段类型、身份、指纹、样本命中与安全边界进行确定性验证，将合法 RulePlan 转换为 GatherSpec，并固定 provider、model、promptVersion 与浏览器 snapshot 时点。Python 执行 Worker 只解释已发布 GatherSpec，不读取模型配置或调用模型。两者采用独立工作负载身份和权限边界。
- 1.0 单组织自托管使用 PostgreSQL 持久化领域对象、不可变 RuleVersion/RuleAttestation/AuditEvent、幂等记录、Operation 与 leased job；SQLite WAL 保留为评估和本地开发路径。实例使用受保护的 Ed25519 签名密钥、独立凭据加密主密钥与本地 Artifact 目录，密钥及数据的一致备份和空实例恢复是发布验收条件，开发样本不替代运维证据。
- Web 控制台采用 pnpm、Vite、React、TypeScript、Tailwind CSS 与 shadcn/ui；浏览器只通过 `/api/v1` 访问控制面，类型生成自 [`contracts/openapi.yaml`](./contracts/openapi.yaml)，不读取数据库、对象存储凭据或 Worker 内部状态。
- 后续平台拓扑以 PostgreSQL 为系统记录、Redis 为可恢复工作分发、S3 兼容对象存储保存 raw/Artifact，并采用托管 KMS/HSM；这些组件不构成单组织 1.0 的安装前置条件。
- GatherSpec 统一使用 JSON，并通过 `extrio.gather.v1` Schema、固定提取语义、ruleDigest 和独立 RuleAttestation 校验。
- 1.0 使用持久化 Schedule、数据库事务队列和租约，不引入 Temporal；Redis Streams 分发属于后续平台拓扑。
- 本地多用户与角色（administrator、engineer、reviewer、viewer）属于公开 Alpha 能力：首次设置创建 administrator，认证使用 Argon2 密码哈希和服务端可撤销会话；外部 OIDC/SSO、MFA、多租户隔离、审计导出、Tenant 授权和独立工作负载身份仍为生产演进边界。
- 同一 Python 代码库可以承载控制面、编译与执行模块，但部署、数据写入、网络权限和运行生命周期必须保持逻辑隔离。
- 探索和 Run 通过持久化 Operation 以 `202 Accepted` 启动；阶段、指标和终态由服务端事实驱动，页面刷新通过 `activeOperationId` 或 `operationId` 恢复，不得由客户端定时器伪造。
- Source 入口只允许 HTTP(S)。匿名公共 HTTP 默认允许，TenantAdmin 可以在界面采集策略中关闭；任何携带凭据的访问必须使用 HTTPS。该策略不放宽 exact allowedHosts、私网/metadata 阻断、DNS 复检、重定向复检、速率或资源预算。
- 所有服务边界、消息 envelope、失败语义与演进阈值由权威合同、OpenAPI 和版本化 JSON Schema 定义；实现不得以框架或采集库默认行为替代合同。

## 7. 版本与变更治理

### 7.1 独立版本

- 文档体系版本使用 `vMAJOR.MINOR.PATCH`。
- 产品发布版本独立编号，例如 `v0.6`。
- GatherSpec 兼容版本使用稳定标识，例如 `extrio.gather.v1`。
- RuleVersion 是业务实体版本，不与文档或产品版本复用。

### 7.2 版本变化规则

- `MAJOR`：产品边界、核心不变量或已发布合同发生不兼容变化。
- `MINOR`：新增向后兼容能力、对象或约束。
- `PATCH`：不改变行为的澄清、链接或文字修正。

### 7.3 审批与落地

1. 产品合同、领域模型、运行时合同、安全合同或 ADR 发生行为变化时，必须先更新相应文档及版本矩阵。
2. 产品负责人审批产品范围和验收合同；技术负责人审批领域、运行时、安全和 ADR。
3. 代码、数据库迁移、API、Schema 和测试必须引用对应的 `FR-*`、`NFR-*`、`INV-*` 或 `AC-*`。
4. 破坏性变更必须包含迁移、兼容窗口、回滚路径和受影响对象清单。
5. 文档进入 `Confirmed` 后才能作为发布阻断合同；该文档体系经责任人明确批准后统一进入 `Confirmed`。
6. 每个产品版本至少复审一次权威矩阵、外部依赖、容量基线和安全边界。
7. 每次待审批文档集必须生成 [`releases/v0.2-docset-manifest.json`](./releases/v0.2-docset-manifest.json)，记录每个权威文件的 path、version、SHA-256、生成时间和文档集状态；批准后追加 `approvedBy`、`approvedAt`、产品版本和 repository revision（存在 Git 时），不得重写已批准快照。

## 8. 权威术语

- **CollectionTemplate**：可复用的数据合同模板。
- **TemplateVersion**：已发布且不可变的模板版本。
- **Collection**：一个业务采集目标的稳定身份。
- **CollectionVersion**：Collection 在特定时点冻结的数据合同版本。
- **Source**：经授权访问的站点或数据来源身份及安全边界。
- **AccessProfileVersion**：认证类型、精确注入作用域和 Secret 引用的不可变访问配置版本。
- **Collector**：Source 与 CollectionVersion 的执行绑定。
- **CollectorOverride**：作者态的、类型受控的 Source 例外配置。
- **RuleVersion**：Collector 的已编译不可变执行规则。
- **RuleAttestation**：对 RuleVersion digest、批准决定、评审策略、发布目的和 SigningKey 的追加式证明。
- **Schedule**：触发 Collector 运行的版本化 Cron 配置。
- **Run**：固定规则和输入上下文的一次执行。
- **RunAttempt**：Run 的一次可恢复执行尝试。
- **RunFinalization**：冻结 winning Attempt、质量决定及 accepted/rejected set 的不可变终结记录。
- **HarvestItem**：租户、Collection 与 Source 范围内的逻辑实体。
- **HarvestItemRevision**：HarvestItem 内容变化形成的不可变版本。
- **HarvestObservation**：一次 Run 对某个 HarvestItemRevision 的有效观察记录。
- **ItemEvent**：HarvestItem 的有序 upsert/tombstone 状态转换，previousEventId 形成不可变事件链。
- **Delivery**：一个 Item 事件向一个 Sink 的逻辑交付。
- **RedeliveryRequest**：对既有 Delivery 追加发送尝试的受控人工命令。
- **Artifact**：原始响应、样本、日志或验证报告等不可变证据对象。
- **ArtifactManifest**：按 metadata_only、sampled 或 replayable 等级记录响应、URL、runtime 与 Artifact digest 的证据索引。
- **ArtifactManifestChunk**：replayable Manifest 引用的有序响应证据分片。

### 概览看板时间范围

概览看板同时呈现今日采集、本周运行成功率、本月有效数据和当前规则覆盖，使日、周、月经营口径可以并列比较。日、周、月只作为“采集产出趋势”的聚合粒度，分别覆盖最近 14 天、12 周和 12 个月；柱形按接收与拒绝数据堆叠，运行质量面板同步说明该趋势范围内的成功、部分成功、失败和数据通过率。经营指标通过 `GET /api/v1/overview?timezone=<IANA>` 在服务端全量聚合，不受列表 200 条上限影响。按浏览器时区的自然日、周一和自然月划分半开区间，运行按持久化创建时间归桶；成功率分母仅包含已终结运行，取消/超时计失败，活动运行单列。本月实体先按来源与 entity key 取最新观测，再按该行 UTC 入库时间判断月份；历史 observedAt 展示字符串不用于时区推断。页面提供快照时间和刷新，失败显示无法确认而不是零或健康。需要关注区域使用来源及最近运行列表，只展示最多三项，不作为全量异常统计。
