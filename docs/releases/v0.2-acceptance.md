# Extrio v0.6 发布验收合同

## 1.0 交付范围

1.0 的交付范围为单组织自托管稳定版，面向一个组织内的数据运营团队，保留本地账号角色、SQLite 评估和 PostgreSQL 部署路径。多租户、SSO/MFA、分布式高可用和移动端不属于本次交付范围。全站页面的内容组织、桌面布局、操作流程和状态反馈属于 1.0 的体验验收范围，不以功能测试通过或单纯调整样式代替。具体页面方案需以真实界面走查和用户复核为依据，沿用唯一正式前端。

1.0 的功能、AC/NFR、部署依赖和退出条件以[单组织自托管验收范围](../planning/v1.0-scope-matrix.md)为版本适用合同。功能实现、工程验证、页面设计签收和生产目标达成分别记录，不将范围确认视为已实现或已验收。

## 自托管可靠性

运行正常达到配置页数上限且没有拒绝记录时记为成功，保留 max_pages 停止原因，结果页明确数据已保存；不显示等待处理或修订规则入口。有拒绝记录或抓取异常时保留异常处理状态。按页数完成不等于完整遍历时间范围，因此该停止原因不推进增量水位，避免跳过尚未遍历的数据。

列表发现与运行共用下一页地址解析：支持普通 href 和受限的静态 location.href 字符串赋值（可包装 encodeURI），不执行页面脚本。可识别的下一页必须通过发现阶段验证，不能以关闭分页或错误的查询参数分页规避；任务证据以具体分页错误码和字段路径呈现失败原因。

API 存活与实例可工作分开表达：`/healthz` 只报告存活，`/readyz` 检查同库 Worker 心跳、代码/合同/共享配置一致性及已使用密钥状态；设置的系统页提供真实 Worker、队列和恢复原因，不以读取失败显示健康。运行页按持久化 Operation 轮询，工程师或管理员可取消；运行中先显示取消已请求，只有持久终态才显示停止。失败原因按网络边界、访问、结构、预算和实例问题给出操作提示，不静默绕过授权或发布修复规则。

Run、Items、Checkpoint、Operation、Webhook 入队和 job 完成在有效租约事务内提交；过期 Worker 不得提交结果或错误，取消/超时不推进 Checkpoint。Webhook 使用稳定 Delivery ID、独立租约和有限重试；人工恢复保留历史，不因地址版本变化静默改投。单组织认证保护首次/最后管理员、角色边界与会话撤销，规则证明使用实际发布主体，不宣称四眼审批。

本地证据按 available/missing/expired/corrupt 等真实状态展示；sampled/metadata_only 不启用等价回放，失败终态不自动显示结果集已冻结。Worker 定期清理到期 raw，保留 manifest 摘要。全量离线备份包括 SQLite/PG、Artifact、当前签名 key 和完整凭据 keyring，恢复只接受空目标；缺失密钥和半恢复不得通过自动生成密钥或清除保护标记变成成功。密钥轮换保留可解密代际和历史公钥。

支持范围、HTTP/浏览器限制、双数据库恢复、安装/readiness、API/MCP 交接与停止方法见[自托管运维手册](../self-hosted-operations.md)。固定来源样本、短期基准和 72 小时观测启动是工程证据，不等于外站/真实模型验收、月度 SLA 或 RPO/RTO 达标；持续观测结果由 G4 分析，用户设计与产品签收独立。

API 与 Worker 的初始化按数据库串行执行：SQLite 同机文件锁覆盖首次 WAL 设置、迁移和补齐；PostgreSQL 会话锁覆盖迁移和补齐。并发启动不得重复执行迁移或使 Worker 因建表冲突退出。

审核字段样本来自实际提取结果，验证样本计数使用真实预览记录；发布确认展示当前登录主体。需求字段与活动版本一致时标识为已发布字段，未保存编辑仍作为草稿。投递记录在配置面板可见期间每五秒刷新，空列表也能发现后台新交付；页面失焦时不持续后台轮询。

## 自适应网页证据验收

- 完整 explore 流程验证业务 URL 别名合同；内部 detailUrl 不要求出现在业务输出，但列表到详情样本的交接仍必须匹配。同一证据下连续三次未解决已有问题的纠错停止，不因原始提案变化绕过保护。

- HTML DOM 与 JSON 快照目录覆盖完整节点索引；目录和长节点可分页，错误节点、跨快照游标、文件路径与任意 URL 请求被拒绝。
- 新任务生成、修复、补读、无效动作与重试共享 16 次调用、120000 输入 token、16000 输出 token、240 秒预算；发现最多 12 次，为编译与校验保留 4 次。恢复包括已消耗预算与停机间隔，不提高历史调用上限。批量读取按上下文余量分配，具体字段错误反馈可用于纠正；连续三次无新证据或新提案停止。未知 usage 不能免费重试，合同过大在调用前失败。
- 固定合同、字段类型、身份与质量门不可被模型修改；完整快照验证覆盖所有详情样本，缺失字段、标题不一致、URL 交接或实体冲突反馈后有界补读，失败不发布、不修改生产 Item、不覆盖原候选。
- 配置 API 与 OpenAPI 支持可选 limits，严格拒绝布尔值、小数、缺失项、越界及无输入空间的组合；旧配置与全量更新兼容。8K、16K、32K、128K 的受控档位验证不替代具体型号实测。
- 中英文模型设置与任务诊断在四个支持桌面视口无关键溢出，历史诊断缺失不伪造成功，读取量不声称准确率。日志和 API 只保留节点标识、范围、摘要、预算及稳定诊断，不复制原始网页或模型内容。
- 工程、浏览器和有界真实模型证据见 [自适应证据执行记录](../reviews/adaptive-page-evidence/execution.md)。工程验证、真实模型结果、人工发布与用户验收分别记录。

## 核心操作上下文

来源执行反馈验收覆盖：已受理探索/修复/运行默认打开执行日志弹窗；收起不取消任务且轮询不重新打开；完成与失败保留日志入口；新任务再次默认打开，刷新后最近 AI 日志按需打开。中文与英文在四个支持桌面视口无关键溢出。导航超时仅在原有预算内重试一次，安全拒绝不重试，无响应不报告 HTTP 0；原始第三方堆栈不进入用户页面。

规则审核的字段警告逐项显示字段标识、验证问题与“修复此字段 / 查看证据”操作，并说明样本缺失不等于来源没有内容。修复入口自动带入当前字段与警告作为本次说明，经确认后调用既有 AI 修复任务，保留输出合同与人工发布门。工程师/管理员以外角色、归档来源、活动任务与待迁移状态不能发起修复。取消不提交；请求失败保留修复说明供重试，不自动排除字段或接受风险。可选字段排除后不再输出；接受风险不会补齐缺失值，界面不承诺修复必然成功。

来源、运行、AI 任务和数据详情通过安全的站内 returnTo 保留入口筛选及 section 分区，返回不丢失来源页面的上下文。搜索可独立清除，刷新保留筛选；首次读取失败提供重试，不显示伪空列表，后台错误保留已读取数据。运行时间使用持久化 ISO 时间，不把历史运行显示为“刚刚”。正文中的 HTML 仅以惰性解析后的纯文本阅读或转义源码显示，不挂载源站脚本、图片和 iframe。来源概览区分已发布规则与最近异常运行；只读角色不能触发来源执行、定义/规则/策略修改或 Webhook 发送。接入表单的录入和导入预览具有离开确认，刷新/关闭使用原生未保存提醒；提交失败保留输入，成功创建可进入详情。设置弹层关闭后恢复原操作按钮焦点，退出失败保留会话并可重试。

## 来源生命周期与所属需求

来源支持需求内新增、基本信息编辑、保留历史的来源删除、归档恢复和独立的所属需求调整。工程师与管理员可执行管理命令，审核发布沿用现有角色边界。来源列表与详情、需求关联来源表提供统一管理菜单；列表默认仅显示活动来源，已归档筛选与搜索、需求条件一起写入 URL。归档来源在需求详情仍可追溯，但不计入可执行来源覆盖。

生命周期 `active|archived` 与规则探索/发布状态分离。归档原子关闭调度，禁止探索、修复、发布、运行与执行配置修改；恢复不启用调度、不启动任务或重发历史投递。实际排队、已领取、运行中的任务及未完成字段迁移阻断归档、删除、定义编辑和归属调整。调度领取后创建运行前再次验证来源状态。

删除来源不可恢复，但不删除规则、运行、数据、操作、AI 任务、证据、策略、调度历史、Webhook、投递或历史归属。已完成的历史不阻断删除；排队或执行中的任务、未结束运行和未完成迁移阻断。删除原子关闭调度、写入不可恢复墓碑，将来源从列表、需求关联与来源统计排除，并释放 URL。重新添加同一 URL 创建独立身份，不继承旧规则、数据、调度或 Webhook。归档可恢复且保留 URL 占用。

删除弹窗显示最新名称、URL、保留的历史数量及操作影响；只有最新预览允许删除时才显示名称确认输入，阻断时显示实际原因与处理方式。重新加载预览后重新输入名称确认。历史运行、AI 任务和数据标记“来源已删除”，保留内容与证据访问，不提供已删除来源的跳转、审核、修复或执行入口。已有投递仍按原合同处理，不因来源删除重发或取消。

基本信息编辑使用 managementRevision 乐观锁；仅改名保留规则，修改采集意图或规范化入口则关闭调度，清除候选、活动规则与 Checkpoint，后续需重新探索、审核发布。所属需求通过独立的目标选择、字段差异和影响预览确认，不混入基本信息编辑。目标必须是不同的活动需求，确认固定目标版本、revision 和全部差异；来源采用目标意图，历史规则、运行、数据与投递 payload 不重写，Webhook 配置保留。

Run、AI 任务、Operation 和 Item 的历史需求归属来自独立不可变记录，以 `collectionAttribution` 返回，不能用当前来源归属解释旧记录。已有历史的来源调整归属后停止调度并撤销旧规则的后续执行资格，新运行须重新探索、审核发布。无法可靠还原历史归属时列出具体记录并阻断调整，不猜测回填。列表、详情和两侧需求缓存同步刷新；提交中禁止重复操作和关闭，失败保留输入并复用幂等键，预览过期明确重载，删除从详情返回原筛选列表。

## 数据查询与导出

数据页使用 `GET /items?view=entities`，服务端按 `collectorId + 历史 collectionId + entityKey` 选择最新观测后应用筛选，返回匹配实体总数、全局筛选选项和游标。页面每次加载 50 个实体，支持继续加载至游标结束；筛选变化重新开始分页，读取失败显示错误与重试。`q` 对标题、正文、来源名称和 entity key 做字面子串搜索，`sourceHost`、`collectorId`、`decision` 为精确筛选。CSV/JSONL 导出复用相同的实体视图和全部筛选，覆盖全部匹配数据而非仅已显示页；超出已有导出上限明确拒绝，不静默截断。默认 API 仍提供观测视图，`entityKey` 仍表示精确匹配。桌面工具栏的搜索区可收缩，导出操作在最小支持视口中可达；宽表格在自身区域滚动。

字段变更比较保留 JSON 类型，`null`、`0`、`false`、空字符串、空数组和空对象不合并为同一值；对象键顺序和数值等价表示不制造 Revision。有效变化追加 Revision 并进入已配置 Sink 的交付队列，不重写历史结果。

## 字段版本与受控迁移

字段草稿、不可变 CollectionVersion 和来源活动 RuleVersion 是三个独立状态。工程师或管理员可编辑草稿、应用模板和请求字段建议；审核者或管理员可发布字段版本、审核并启动或放弃来源迁移。字段发布冻结字段列表、JSON Schema、去重标识、变更检测字段及完整语义摘要；至少包含一个必填去重字段和一个变更检测字段。发布使用预览时的 revision、幂等键和原子审计，历史版本只读。有来源、已发布版本或字段建议审计历史的需求禁止物理删除，可归档。

新来源在创建时绑定需求活动字段版本，后续修改草稿或发布版本不会修改该绑定。尚无已发布版本的需求保留旧静态合同兼容路径，不将草稿视为已发布合同。固定版本的编译、预览、人工发布和运行使用同一不可变合同；缺失、跨需求或不匹配的版本不能静默回退。规则修复保留固定合同，运行不能由模型或可变草稿扩展业务字段。

来源迁移计划固定目标版本、差异及摘要，逐项确认所有字段增删改；运行、编译或审核操作进行中时禁止切换。确认迁移仅创建待重编译状态，当前绑定和活动规则保留；候选须通过重新生成、预览、审核和人工发布，发布事务才切换版本。失败显示真实原因，可重试或明确放弃。放弃不修改活动规则；来源定义未修改时恢复迁移前候选与审核状态，定义已修改时清除不适用候选并要求重新生成。旧版本和历史运行不重写。

内置公共公告、产品目录、活动日历模板使用稳定版本标识，预览展示字段差异，确认后替换保存的草稿而不发布。AI 字段建议复用默认模型供应商及网关，通过独立持久任务队列由 Worker 执行，不伪装为来源 AI Run。模型输入仅为需求名称、最多 4000 字目标及最多 50 个草稿字段的受限摘要，不发送网页样本或凭据。每需求最多一个活动任务、每小时最多五次请求；模型输出须通过 1–32 个字段的结构和语义校验。任务有 120 秒租约、最多三次领取及尝试 fencing，模型调用有超时与成功/失败、usage、摘要审计。

字段建议入口保留最近 20 个任务及排队、生成、失败、可选择、已应用状态，刷新恢复持久结果。建议完成不自动修改草稿，用户逐字段选择后按 key 合并；过期 revision 拒绝应用，失败保留选择及本地输入。未保存本地字段编辑时禁止模板和建议应用入口。字段版本、模板、建议与迁移界面共用正式前端，中英文桌面验收范围一致。

## 单前端实现边界

需求详情的“添加来源”在当前页面打开弹窗，固定提交当前 Collection ID，不提供切换或新建需求选项。支持逐行输入多个精确列表页入口，校验无效与重复地址；创建成功后刷新需求详情、需求列表和来源列表，并定位“关联来源”。部分失败明确显示逐项原因，仅保留失败入口供重试；请求失败保留输入，同一请求重试复用幂等键，提交期间禁止关闭，放弃输入需确认。已有来源不按需求名称自动迁移，重复地址由服务端明确拒绝；该入口不自动探索或发布来源。文件批量导入保留在采集来源工作面。

Extrio 只有一套正式前端：`web/index.html` → `src/main.tsx` → `app/router.tsx`，共享 AppShell、AuthGate、QueryClient 与 API 客户端。一级导航为概览、采集需求、采集来源、运行、数据、设置。需求列表读取独立持久化的 Collection，点击进入 `/collections/:collectionId` 明细，展示完整目标、字段要求、来源执行合同与关联来源；明细支持添加来源，来源归属链接返回需求明细，需求列表的搜索、状态筛选和更新时间排序通过 URL 保留，详情返回不丢失列表上下文。需求列表把名称与两行目标摘要放在同一业务单元，按来源发布覆盖、最近更新时间和合同引用进行比较；使用中、已归档和全部筛选显示各自数量，清除搜索只清除关键词，刷新保留当前条件。初始加载与失败不显示零需求，空列表、当前状态为空和搜索无匹配分别提供反馈。合同引用与来源发布覆盖不代表统一字段版本已冻结、调度开启或运行健康。需求支持独立新建、名称与业务目标编辑、空需求删除、归档和恢复；工程师与管理员可操作，其他角色只读。有关联来源的需求禁止删除；归档禁止编辑需求与添加来源，不停止已有来源、定时采集或运行，不删除历史数据。编辑使用 revision 冲突校验，不覆盖已有来源采集说明及不可变规则；新来源使用当前业务目标。模型、凭据、审核、运行与数据保留现有后端能力。旧 `experience.html` 地址仅用于兼容跳转，不提供独立应用或模拟业务数据。

需求详情以“采集字段 / 关联来源”组织工作面，字段仅展示一次。头部集中需求身份、使用/归档状态、来源发布覆盖与更新时间，长目标或多段目标支持摘要与全文展开。当前分区通过 section=sources 写入 URL，采集字段为默认分区；刷新恢复分区，返回列表保留 q/status/sort 且不携带详情 section。字段名称、技术标识和业务说明归入同一列，编辑操作列固定宽度；来源覆盖和约束差异在同行表达，按需打开该字段的来源详情与完整合同。字段草稿支持手动增改删、名称、标识、类型、必填、去重标识、变更检测与说明，真实保存到 Collection，使用 revision、权限、幂等和审计保护。没有草稿时按 key 合并来源输出，每个字段一行，差异保留而非视为统一已发布合同；有草稿时以草稿为主，来源额外字段可按需展开且不自动写入草稿。来源已发布字段只读取不可变活动 RuleVersion，候选规则另行标注。来源合同差异和草稿缺失字段可见，完整输出 Schema 与质量规则可查。字段编辑采用顶部保存操作条，长表编辑时持续可达。未保存标记在分区标签中可见，分区切换保留本地字段草稿；应用内跨页面离开需确认，浏览器刷新/关闭保留原生提醒，保存期间不允许通过离开确认放弃正在提交的内容。后台详情读取失败保留已有数据和本地字段编辑，失败与 revision 冲突不自动覆盖输入，放弃重载使用明确动作。字段编辑和来源证据弹层关闭后恢复触发位置。关联来源把名称和入口网址归组，状态与真实输出字段数并列；合同未知或不可用显示无法确认，不解释为零。草稿不自动应用于新旧来源或运行，不等于字段版本发布。字段版本、模板、AI 建议和来源迁移遵循下述独立确认流程。设置分为系统设置和模型设置两个 URL 同步页签（`?tab=system|models`）。系统设置包含语言、账号、环境及管理员专属的采集策略与用户管理；模型设置保留供应商、模型、默认模型及凭据管理，非管理员只读，读取失败提供重试且不得显示为空配置。桌面下限为 `1024px`，主验收 `1440x900`，补充 `1280x800`、`1132x1028`、`1024x800`；宽表格在自身区域滚动，移动端不在范围内。

设计见 [核心体验重构方案](../core-experience-redesign.md)，实现与验收见 [前端说明](../experience-prototype.md)。

## 2. 发布目标

v0.6 必须证明 Extrio 可以把一个支持范围内的 Source 从数据意图推进到已审核的 RuleVersion，并在不调用 LLM 的运行时中持续采集、规范化、交付、告警、回放和审计。

发布以可运行的纵向闭环为标准，不以对象页面或接口数量为标准。

## 3. 进入验收条件

1. [`../SSOT.md`](../SSOT.md) 权威矩阵中的 v0.6 文档均为 `Confirmed`。
2. 数据库迁移、`extrio.control-plane.v1` OpenAPI、GatherSpec Schema、Worker runtime 和 UI 版本已经冻结为候选版本。
3. 所有自动化测试在与生产同类的环境中执行。
4. 1.0 验收需要单组织测试账号、Source、模型、Webhook 接收端、数据库、Artifact 与受保护密钥目录及故障注入能力；Kafka、对象存储集群和 Secret Manager 属于后续平台拓扑的专项验收依赖。
5. 每个候选构建具有不可变制品 digest、依赖锁、SBOM 和部署记录。

## 4. 阻断条件

以下任一条件存在时不得发布：

- 跨租户读取、写入、执行或对象引用。
- 凭据明文进入 URL、规则、Redis、日志、Artifact、ArtifactManifest 或输出。
- Published RuleVersion 可被更新，或 Worker 可执行 digest/RuleAttestation 无效的规则。
- 运行期可访问 LLM 或执行用户代码。
- Source SSRF 可到达内部网络、metadata 或未授权主机。
- 重复调度、Worker 恢复或队列重建产生不同逻辑 ItemEvent/Delivery。
- 采集失败、预算耗尽或必填质量门失败被显示为完整成功。
- 生产回放没有额外授权或可以越过默认无副作用边界。
- P0/P1 缺陷未关闭；高危已知漏洞未修复或未获有期限风险批准。
- 设计容量、RPO/RTO 或关键用户旅程没有真实证据。

## 5. 端到端验收场景

### `AC-001` 创建并冻结 CollectionVersion

**映射：** `US-001`、`FR-001`、`FR-002`

1. CollectionEditor 从 Published TemplateVersion 创建 Collection，并修改允许的字段和质量门。
2. 缺少身份字段、无效 Schema 和未声明输出字段必须被拒绝并定位到具体字段。
3. 有效版本完成验证并冻结。
4. 冻结版本无法更新；变更操作创建新 CollectionVersion。

**证据：** API/UI 旅程测试、Schema/语义反例测试、数据库不可变约束测试和 AuditEvent。

### `AC-002` 批量接入 Source 与访问边界

**映射：** `US-002`、`FR-003`、`FR-004`、`FR-014`

1. 使用 UTF-8 CSV/TXT 导入至少 100 个精确 Source 入口，其中包含带引号和字段内逗号的 CSV、URL 表头别名、HTTPS、获批匿名公共 HTTP、未获批 HTTP、站点根目录、重复 URL、非法协议、非 `exact` mode、跨 Tenant AccessProfile 和未授权域名样本。
2. CSV 的 `mode` 可省略并默认为 `exact`；当前只支持 `exact`。系统在固定高度预览中显示文件名、行号、字段、`scopeHint`、逐项状态和筛选，只提交合法项并建立 SourceRevision 与 Collector；重新选择文件替换当前文件条目并保留手动条目，同 URL 的文件结构化元数据优先；非法项具有稳定错误码，站点根目录不得作为运行入口。
3. 文件级格式、表头、编码、大小和行数错误以警告呈现，并保留最近一次成功解析的文件预览；用户可以一次清除全部文件条目，手动条目保持可用。
4. SourceRevision 固定 entrypoint、allowedHosts、transport、速率、体积和合规依据。
5. 匿名公共 HTTP 只有在 TenantAdmin 策略显式接受风险时可以建立 Source；任何 AccessProfile 或凭据请求仍必须使用 HTTPS。
6. 任何 secret 明文均不能进入 Source、Collector 或导入错误报告。

**证据：** 批量导入测试、Tenant 隔离测试、secret 扫描和逐项结果快照。

### `AC-003` 编译、验证、发布与回滚

**映射：** `US-003`、`FR-005`、`FR-006`、`FR-015`、`NFR-001`、`NFR-002`

1. 编译以 Source 样本和 CollectionVersion 为输入，由默认模型产生合法 `extrio.rule-plan.v1`，平台验证后产生 GatherSpec、编译谱系、ArtifactManifest、样本 Artifact、字段预览和质量报告。
2. 非法 selector、外部 `$ref`、敏感 Header、越界 URL、缺失身份和不支持 runtime 规则不能进入 NeedsReview。
3. CollectionEditor 无法发布；RuleReviewer 批准后发布事务原子切换活动版本。
4. 仅拥有 TenantAdmin 的用户无法发布、回滚、reprocess 或 redeliver；多角色用户必须显式满足对应角色。
5. Run 创建后发布新版本，该 Run 仍使用旧版本。
6. 回滚只切换活动指针；历史 GatherSpec、digest 和 Run 不变化，无当前有效证明时先追加 RuleAttestation。
7. RuleAttestation 签名绑定 approval、review policy 和 evidence digest；任一字段篡改均被拒绝。
8. SigningKey Retired/Compromised 与重新证明按合同阻断或恢复新 Run，不修改 RuleVersion。
9. Collector 名称修改保留活动规则与可运行状态；采集意图或 Source 入口修改清除当前候选并阻断新 Run，直到新候选完成审核发布，历史 RuleVersion、RuleAttestation 与 Run 均不变化。
10. 规则编辑表单按执行顺序集中展示可修改的列表 Item selector、可编辑网页业务字段 selector、分页参数、`detailUrl` 交接和输出字段 selector；系统管理字段不进入编辑表单；不可编辑的请求配置、字段语义、安全边界和输出合同只在 JSON 中按需查阅，不在表单重复展示。直接编辑两个阶段的 selector 或分页参数时，系统创建受控 Override 和新候选 digest，清空旧审核决定，并使用最近探索样本完成 GatherSpec Schema、详情发现和必填字段质量验证；字段语义保持 CollectionVersion 锁定，验证失败不能进入可发布状态。

**证据：** 权限测试、规则 fixtures、事务故障注入、RuleAttestation/密钥事故验证和并发发布/触发测试。

### `AC-004` HTTP page 型 list/detail 运行

**映射：** `US-004`、`FR-007`、`FR-009`、`FR-010`

1. 使用多页 HTML fixture，list 提取列表标题和 detail URL，detail 提取详情标题、发布时间和正文，Run 写入采集时间。
2. 重复页、空页、最大页数、超时和响应过大均按合同结束。
3. 相同响应重复执行产生相同 entityKey、outputContractDigest、payloadFingerprint、revisionKey 和 eventId。
4. 内容或输出合同变化创建新 Revision；未变化默认不创建新 ItemEvent，但每个有效 Run 创建 HarvestObservation。

**证据：** golden fixtures、属性测试、预算测试、运行统计和谱系查询。

### `AC-005` next_link 与受限浏览器运行

**映射：** `FR-007`、`NFR-001`、`NFR-008`

1. next_link 在 allowedHosts 内正常翻页，循环链接被检测并停止。
2. 跨未授权主机、DNS rebinding、私网地址和 metadata URL 被阻断。
3. 获批匿名公共 HTTP 可在无凭据边界内运行；携带 AccessProfileVersion 或凭据的请求只能使用 HTTPS。redirect 不继承凭据、不能降级，并对目标重新执行 exact origin/path scope。
4. 浏览器上下文按 Run 隔离，下载和内部网络不可用，结束后无 cookie/local storage 残留。
5. Worker 不能访问 LLM 或执行规则外代码。
6. browser Rule 固定 engine/version、viewport、locale、timezone 与 Unicode 版本；回放消费 canonical DOM snapshot，不重新执行 JavaScript。

**证据：** SSRF 套件、浏览器隔离测试、网络策略测试和进程资源报告。

### `AC-006` 调度、租约、取消与恢复

**映射：** `FR-008`、`FR-009`、`NFR-003`

1. 双调度器处理同一 occurrence 只创建一个 Run。
2. Worker 在处理中失联，新 Attempt 接管；旧 Worker 因 fence token 无法提交。
3. 取消和超时保留 staging 与证据并明确标记不完整，不提升生产 ItemEvent 或 Delivery。
4. v0.6 固定 overlapPolicy=forbid。支持范围内的时间降序 `next_link` Source 必须固定 CollectionPolicyVersion、运行窗口与 Checkpoint 前值；仅成功终结推进 Checkpoint，预算截断、部分成功、失败、取消和超时保持原值。

**证据：** 并发测试、进程终止故障注入、状态机测试、Checkpoint 原子提交测试和预算截断反例。

### `AC-007` Item 与幂等一致性

**映射：** `FR-010`、`NFR-002`、`NFR-003`、`NFR-006`

1. 相同身份、输出合同和内容在请求重试、Attempt 重试和队列重复下只创建一个 Revision/Event，每个 Run 仍有唯一 Observation。
2. 身份为空或类型转换失败按 onError 处理，不产生不稳定 entityKey。
3. Source 缺失历史实体不会自动产生 tombstone。
4. 相同 payload 在 outputContractDigest 变化后产生新的 revisionKey，旧 Revision 不被覆盖。
5. 同一 Run 的同 entityKey/same revision 重复项合并并记录 occurrenceCount；不同 revision 产生 `ITEM_IDENTITY_CONFLICT`，不按完成顺序覆盖。
6. 从 ItemEvent 可追溯完整规则、观察、运行、数据合同、Source 和 ArtifactManifest。
7. A→B→A 与 tombstone→恢复产生新的转换 eventId；同一转换重试复用 eventId。
8. 质量门、duplicate conflict 和 Run outcome 在 Delivery outbox 释放前完成；Failed/Cancelled/TimedOut 不产生可发送 Delivery。

**证据：** 幂等压力测试、数据库唯一约束测试、谱系查询和数据丢失核对报告。

### `AC-008` Kafka 与 Webhook 交付

**映射：** `FR-011`、`NFR-003`、`NFR-006`

1. Kafka message key 为 eventId，Kafka 与 Webhook body 均通过 ItemEvent Envelope Schema，并包含 deliveryId 与完整谱系。
2. Webhook 具有 Idempotency-Key、Content-Digest、时间和域隔离 HMAC 签名；篡改 body、timestamp 或 digest 均失败。
3. `429/5xx` 重试，永久 `4xx` 直接失败，UnknownOutcome 复用同一 deliveryId。
4. 超过窗口进入 DeadLettered 并告警；Run 采集状态不被改写。
5. 同 SinkVersion 人工 redelivery 复用 Delivery/deliveryId 并追加 RedeliveryRequest/Attempt；新 SinkVersion 创建新 Delivery。
6. 新绑定 SinkVersion 在下一次有效 Observation 时为既有 ItemEvent 创建缺失 Delivery，不创建伪造的新事件。
7. DeadLettered redelivery 成功后 Delivery 进入 Delivered，失败仍保持 DeadLettered；Delivered redelivery 由 Request 独立记录且不回退原状态。

**证据：** Sink contract test、模拟故障、重复检测、签名验证和 DeadLettered 告警。

### `AC-009` Artifact 与三种回放

**映射：** `US-006`、`FR-012`、`FR-014`

1. metadata_only、sampled 与 replayable 模式具有互斥字段和明确 completeness；rawRetentionDays=0 不得生成伪 replayable 证据。
2. validate_only 无 HarvestItem、Delivery、生产 namespace 或 Sink 副作用。
3. reprocess 需要审批并记录 replay lineage，默认不交付。
4. redeliver 不重新请求 Source，保留 eventId/deliveryId 并记录审批与新 Attempt。
5. 只有完整 replayable Manifest、连续 chunk 与全部有效 Artifact 可以证据等价回放；缺失、断序、digest 错误、跨租户或过期均拒绝。
6. 100,000 item 和大批 list/detail 响应通过上限 1,000 条的 chunk 扩展，root manifest 不内嵌全部响应。

**证据：** 副作用断言、RBAC 测试、对象生命周期测试和 AuditEvent。

### `AC-010` 漂移、告警与恢复

**映射：** `US-005`、`FR-013`、`FR-015`

1. 前 3 个成功 Run 标记 BaselineBuilding；安全/强制质量异常立即告警，历史分布阈值只在 BaselineReady 后使用。
2. 连续 3 次 Failed 自动暂停 Schedule，不自动生成或发布规则。
3. 新样本、新 RuleVersion、人工审核、金丝雀 Run 和活动版本切换构成完整恢复路径。
4. Schedule 间隔不超过 12 小时时在 2 个计划 Run 且最长 24 小时内发现漂移；更低频 Schedule 只按 2 个计划 Run 验收。
5. 告警链接到可操作对象和证据，通知中不包含敏感 URL 或凭据。

**证据：** 基线 fixture、告警规则测试、恢复旅程和无自动发布断言。

### `AC-011` 认证、审计和安全边界

**映射：** `FR-014`、`NFR-008`、`NFR-013`

1. 新实例只允许原子创建首个本地管理员，密码以 Argon2 哈希保存，不提供公开注册入口。
2. 未认证控制面请求被阻断；会话只在服务端保存 token 摘要，并可通过退出立即吊销。
3. 登录使用通用失败响应并限流；跨 Origin 状态变更被阻断，Cookie 使用 HttpOnly 与 SameSite。
4. 规则发布写入真实认证 actor 的不可变 AuditEvent，客户端对象 ID 不能绕过资源边界。
5. 外部 OIDC、多用户 RBAC、MFA step-up、Tenant 删除和独立工作负载身份不属于公开 Alpha 的生产能力声明。

**证据：** 认证 API 测试、会话吊销测试、登录限流测试、审计 actor 断言、容器 E2E 和 secret 扫描。

### `AC-012` Schema、协议和 Runtime 兼容

8. SQLite、隔离 PostgreSQL、OpenAPI/生成类型及中英文四个支持桌面视口均有工程验证证据。合成协议模型用于流程验证，不替代真实模型效果验收。

## 7. 缺陷严重度

| 级别 | 定义 | 发布规则 |
| --- | --- | --- |
| `P0` | 已发生或可直接造成跨租户、凭据泄露、不可恢复数据丢失、任意代码执行或全面不可用 | 立即停止发布与相关生产能力 |
| `P1` | 核心旅程不可用、错误数据/交付、不可审计高风险操作、SLO/RPO/RTO 明确不达标且无可接受绕行 | 必须关闭后发布 |
| `P2` | 非核心退化、局部可用性/体验问题或有安全且明确绕行的缺陷 | 必须有负责人、影响、目标版本和到期日 |
| `P3` | 不影响正确性与安全的轻微问题 | 可进入常规 backlog |

## 8. 证据要求

每个 `AC-*` 必须具有：

- 候选构建 digest、环境和执行时间。
- 测试命令或自动化 job 标识。
- 原始结果、通过/失败摘要和已知限制。
- 关联缺陷及其处置。
- 责任人复核结论。

证据不得由纯文字“已通过”替代。失败测试不能删除或跳过来获得通过状态；例外必须由验收责任人明确接受并设置到期日。

## 9. 发布退出条件

1. `AC-001` 至 `AC-017` 全部通过。
2. 功能、非功能、安全和灾备证据完整且可复现。
3. P0/P1 缺陷为零，P2 缺陷具有用户影响说明和明确处置版本。
4. 监控、告警、暂停、回滚和事件响应路径完成生产前演练。
5. 发布、数据库和规则回滚路径经过验证。
6. 产品负责人和技术负责人明确签署 `Accepted`。

### 概览看板验收

概览看板同时显示今日采集、本周运行成功率、本月有效数据和当前规则覆盖，不得用单一周期切换替代这些并列口径。日、周、月只控制采集产出趋势，分别形成最近 14 天、12 周和 12 个月的 14、12、12 个时间桶；柱形区分接收与拒绝数据。运行质量面板随趋势口径更新成功率、成功/部分成功/失败分布与数据通过率，需要关注面板最多显示三项人工动作。经营指标通过 `GET /api/v1/overview?timezone=<IANA>` 在服务端全量聚合，不受列表 200 条上限影响。按浏览器时区的自然日、周一和自然月划分半开区间，运行按持久化创建时间归桶；成功率分母仅包含已终结运行，取消/超时计失败，活动运行单列。本月实体先按来源与 entity key 取最新观测，再按该行 UTC 入库时间判断月份；历史 observedAt 展示字符串不用于时区推断。页面提供快照时间和刷新，失败显示无法确认而不是零或健康。需要关注区域使用来源及最近运行列表，只展示最多三项，不作为全量异常统计。支持视口内无页面级横向溢出或控件遮挡，宽列表在自身区域滚动。

## 10. 发布后验证

- 阻断级安全或数据正确性问题立即暂停相关能力并按已验证回滚路径处置。
- v0.6 验收证据至少保留 365 天。
