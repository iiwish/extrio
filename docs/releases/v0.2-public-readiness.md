# v0.2 public readiness

This checklist is the release gate for the first public Extrio alpha. A checked item requires
repeatable evidence in the repository or GitHub Actions.

## Product and security

- [x] A new instance requires first-run administrator setup.
- [x] Control-plane endpoints reject unauthenticated requests.
- [x] Passwords use Argon2 and sessions are server-side revocable.
- [x] Login throttling, logout, and secure-cookie behavior have automated coverage.
- [x] Secrets and generated runtime keys are excluded from source and container layers, and CI
  scans tracked source for committed secrets.

## Build and supply chain

- [x] Source, frontend, and backend test suites pass from a clean checkout.
- [x] Docker Compose starts the web, API, and worker services and passes an authenticated smoke test.
- [x] Version-tag release automation builds backend and web images for `linux/amd64` and
  `linux/arm64`.
- [x] Release builds request BuildKit provenance and SBOM attestations.
- [x] Trivy blocks unfixed HIGH or CRITICAL operating-system and library vulnerabilities in
  container verification and release workflows.
- [x] Release automation applies keyless GitHub Actions signatures and provenance attestations to
  published manifests.

## Open-source operations

- [x] Apache-2.0 license, notice, contribution, security, support, governance, and conduct policies are present.
- [x] Maintainers, roadmap, issue templates, pull request template, and CODEOWNERS are present.
- [x] README setup and deployment instructions match the tested release path.
- [x] GitHub repository description, topics, vulnerability alerts, automated security fixes, and
  merge settings are configured.
- [x] The repository remains private until this checklist and the final maintainer review are complete.

## Release evidence

The release engineering is ready. The following activation evidence is intentionally deferred until
a maintainer selects the first release-candidate tag:

- [ ] Push the selected `v*` tag and record the release workflow run.
- [ ] Record backend and web image manifest digests and verify both architecture manifests.
- [ ] Verify the published SBOM, provenance, Cosign signatures, and zero-blocking-vulnerability result.
- [ ] Enable required branch checks after the repository becomes public or the account supports
  private-repository branch protection.
- [ ] Record the final maintainer review and change repository visibility only by explicit decision.

Release notes must also record source CI, Docker Compose E2E, desktop browser QA at `1440x900` and
`1280x800`, and any accepted residual risks.
