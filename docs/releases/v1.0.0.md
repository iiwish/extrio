SQLite 评估、PostgreSQL 16 部署、唯一中英文桌面前端（最低 1024px）。
生产 Run 不调用模型；来源规则须人工审核发布。不新增平台功能、不重做 UI，
不扩大真实来源或模型调用预算。未批准的 P2 设计方案、移动端、PG18、生产部署、
平台级容量和月度 SLA 不属于本轮验收。

## 稳定版剩余门槛

1. 候选本地完整验证通过：后端双库 801 项、0 跳过；发布专项 26 项包含在全量中，涵盖
   实际 RC/Alpha/历史基线升级恢复、sdist/wheel 和 Compose 参数边界。前端 264 项、
   lint/build、双库 272 组桌面旅程、RC 摘要安装与候选本地双库安装、Ruff、OpenAPI、
   文档一致性均通过。源码 secret 为零，候选 arm64 镜像可修复 HIGH/CRITICAL 为零，
   不表示没有未修复告警，也不替代远程或双架构检查。结果与命令以
   [收尾执行包](../reviews/v1.0-stable-2026-09-27/packet.md)、
   [稳定版发布验证](../reviews/v1.0-stable-2026-09-27/release-validation.md)和
   [集成验证](../reviews/v1.0-stable-2026-09-27/verification.md)记录为准。
2. 安全决策待完成：NLTK `GHSA-8mgp-746c-j5xp` 尚无修复版本，保持告警 open，
   不加忽略、不降低扫描门槛。受影响 API 阳性对照、实际应用路径与输入负向证据已通过
   15 项边界及 49 项关联测试，见[安全结论](../reviews/v1.0-stable-2026-09-27/security.md)。
   未观察到调用只适用于测试覆盖路径，不是完整不可达证明。稳定版仍须用户独立接受
   限定残余风险或等待可验证的上游修复；RC 风险接受不等于稳定版风险接受。
3. 候选 PR 必须通过全部必需 CI，结果绑定该 PR 的 head SHA 与 Checks；P0/P1 不得有未处置项，P2 须有明确影响、负责人和期限。
   最终产品/技术签收与依赖风险决策均未取得，不将本交接标记为 `Accepted`。
4. 用户另行批准合并后，稳定版 main 精确 SHA 必须重新通过 CI 与 Container verification。
   用户批准 tag/release 后，稳定版双架构镜像须重新完成扫描、签名及 provenance；
   PR merge SHA、RC 检查或本地镜像均不能代替。生产部署仍单独授权。

## 安装与恢复

升级和恢复步骤见 [1.0 升级手册](v0.7-upgrade.md)。记录源/目标程序和镜像摘要，
停止写入并完成全量备份；恢复只接受空目标，回退使用匹配的源程序与升级前备份，
没有数据库原地降级。已发布 RC 镜像摘要从该 Release 的 `release-verification.json`
取得，不使用 `latest`；源码稳定版本号不得充当已发布稳定镜像的安装地址。
