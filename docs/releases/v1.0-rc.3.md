## 范围与限制

- 单组织自托管、SQLite 评估与 PostgreSQL 16、唯一中英文桌面 Web 前端（最低 1024px）；不新增平台功能、API 或数据库迁移。
- 可靠性修复覆盖恢复批次签名启动拒绝后的批次终结与其他批次推进、来源创建响应丢失后的幂等重试，以及全部拒绝结果的导航；不放宽签名或来源审核规则。[P2 工程回归](../reviews/p2-reliability-20261022/verification.md)属于源码证据，不证明 RC3 制品已通过。
- 目录工具对 1364 个入口做限量、隔离核验，包含 143 个工具异常入口复验及高校、河南交易中心、浙师大三个模板包。矩阵中的 68 个可读样本只证明限量列表/详情可读，不等于经审核签名的生产规则、完整历史、真实增量或长期支持；待适配、受限、无效输入和继承主机停止分别记录。[首轮矩阵](../reviews/catalog-validation-20261023/verification.md)与[复验及模板证据](../reviews/catalog-followup-20261023/verification.md)不作为整站兼容性承诺。
- 采购网首次历史覆盖和真实增量仍未完成；冻结六来源发行记录中的 106 条质量待处理不计有效正文。目录清单、静态样本和离线模板不扩大六来源已有支持边界。
- 保持零付费模型、不写现有业务库、不启用来源调度，不进行真实采集。既有实例未升级；本轮不部署、不迁移或重启既有实例。仅使用独占临时资源和合成账号验证安装。
- 72 小时观测沿用已有豁免，不计为通过；RC 风险接受不等于稳定版风险接受，不新增安全风险豁免。

## 发行门禁

执行授权与分工见 [RC3 执行包](../reviews/rc3-release-20261023/packet.md)。发行准备及回执 PR 遵守现有保护规则；其他既有 PR 不处理，不创建正式 `v1.0.0` 标签。

1. 发行准备 PR 精确 head 检查成功并正常合入后，实际 main SHA 独立通过 CI 和 Container verification。默认 noble 镜像在 amd64/arm64 独立验证浏览器/PDF/EPS、网络负例、完整备份恢复及固定历史/Alpha/RC1 双库升级回滚。
2. 对实际候选双架构制品执行包含未修复项的完整扫描。任何 HIGH/CRITICAL 均阻断，不忽略告警、不更换默认镜像或工作流规避门禁。MEDIUM/LOW 保留完整清单并独立评估；RC2 的漏洞数不能作为 RC3 结论。
3. 精确提交与制品门禁通过后才创建唯一新预发布标签。现有工作流维持 main 祖先、精确提交检查、四组高危扫描、签名、provenance 与晋升前重验；不创建 `latest`，不移动旧标签。失败保持可见并停止发布，不自动重试。
4. 发布后独立核对版本标签与源 SHA 标签的不可变索引和平台摘要，验证精确发行工作流/标签身份的签名及 provenance 的源 SHA/ref。对实际发布的两镜像两架构再次完整扫描，不使用本地重建镜像代替。
5. 使用已验证发布摘要分别执行 SQLite/PG16 隔离安装，检查鉴权旅程与临时容器、卷、网络清理。安装不等于既有实例部署，未核验成功前不声明完成。
6. 本轮 GitHub Release 应附 `release-verification.json` 和 `vulnerability-inventory.json`，包含实际源 SHA、工作流、不可变摘要、工具与完整验证结果；上传后重新下载核对哈希。当前尚无该回执，不提供推测摘要或安装地址。

## 安装与稳定版

升级、空目标恢复和匹配源程序回滚遵守 [升级手册](v0.7-upgrade.md)，没有数据库原地降级。未来安装只使用实际发布且通过签名/provenance 核验的摘要，不使用 `latest`、CI 本地 image ID 或包版本推导的地址。

正式稳定版的来源覆盖、质量待处理、目标用户旅程、候选安全评估及产品/技术签收仍按 [稳定版交接](v1.0.0.md)单独验收。任何 RC3 成功结果仅适用于其精确提交和制品，不授权稳定版或生产部署。
