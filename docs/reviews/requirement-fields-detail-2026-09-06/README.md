# 需求详情与字段要求

## F001 执行合同

用户要求重构需求详情，恢复业务字段预览和编辑。采用 Direct Execute，范围为 Collection Store/API/OpenAPI、统一前端需求详情、字段编辑组件、测试及产品合同，不委派，不改变运行中的规则。

- 详情以字段为主工作面，显示名称、目标、管理状态、更新时间、关联来源及字段要求。
- 需求字段草稿独立持久化，支持增改删、类型、必填、身份字段、变更检测字段及说明；使用 Collection revision、权限、幂等和审计保护。
- 各来源的实际合同来自不可变活动 RuleVersion；没有活动版本时可明确查看候选合同，活动版本读取失败时不得回退为候选并声称已发布。
- 字段预览读取 normalizedItemSchema 和列表/详情规则，不只读取 candidate.fields，保留真实类型与质量规则。不同来源不自动合并，不伪造统一合同。
- 保存字段要求不覆盖活动规则、运行及历史数据，也不宣称草稿已应用；字段版本发布和批量重新编译不属于本次页面重构。

## 设计合同

桌面运营工作面，沿用 192px 侧栏、56px 顶栏、20px 标题与 13px 正文。字段要求/来源执行字段/关联来源为线型页签，字段默认首屏可见；需求目标可展开，元信息单行排列。字段表格固定列，行内编辑采用 Lucide 图标与 tooltip，单字段编辑使用表单弹窗，草稿底部提供保存/取消；表格区域可横向滚动，整页不得溢出。背景、文字和边框使用现有 token；蓝色用于操作，绿色用于发布，琥珀色用于草稿。无装饰媒体或第二套应用。

## 验证与检查

先写失败测试：从活动规则读取完整字段而非候选，草稿保存/刷新/冲突/归档阻断，非法与重复标识校验，已发布规则保持不变。前端测试字段预览、编辑/新增/删除/取消/保存错误保留及只读权限。运行 backend pytest、pnpm test/build/lint、文档清单校验和 1440x900、1280x800、1132x1028、1024x800 桌面截图。

## 验证结果

- 首轮 3 个后端测试因缺少 fieldDraft 写入及 sourceContracts 投影失败；实现后通过。后端全量 `uv run pytest -q` 为 223 passed、16 skipped；PostgreSQL 环境未配置，16 个 PostgreSQL 测试未执行。
- 前端全量 `pnpm test --maxWorkers=1` 为 29 个文件、113 项测试通过。字段测试覆盖预览、只读权限、重复字段阻断、增改删、撤销、取消、失败重试、清空草稿不回退为来源字段及来源差异。`pnpm build`、`pnpm lint`、相关后端文件 Ruff、`git diff --check` 与文档 manifest 校验通过。
- 真实本地 API 验证：北京来源活动规则输出 5 个字段，中央采购来源活动规则输出 7 个字段；页面不使用 candidate.fields 代替完整输出 Schema。没有修改现有需求、来源、规则或运行记录。
- 独立 Playwright Chromium 运行 `desktop_qa.py`：四种实际桌面视口尺寸一致、整页无横向溢出、字段弹窗在视口内、无页面 JavaScript 错误、无 POST/PATCH/DELETE 请求。填写的验收文本已取消，浏览器关闭；内置浏览器停留在用户需求详情，已显示字段预览和独立“编辑基本信息 / 编辑字段”入口。
- 截图：[字段首屏 1440x900](fields-1440x900.png)、[字段编辑 1280x800](edit-1280x800.png)、[来源执行合同 1132x1028](execution-1132x1028.png)、[最小桌面 1024x800](fields-min-1024x800.png)。检查了文字换行、表格约束标签、操作按钮、焦点、字段弹窗及质量指标。元信息保持单行，最小桌面使用正常纵向滚动，不添加移动端布局。

## 交付边界与复核

需求字段草稿已真实持久化；字段版本发布、模板、AI 字段建议及将草稿应用到来源的编译/迁移流程未交付。页面明确标识未应用，不宣称修改了执行规则。前端语义名称词典只为常见技术标识提供可读标签，完整输出 Schema 保留源合同；不同来源不自动合并，追加来源字段仅补充缺少的 key。
