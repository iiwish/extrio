# 采集需求管理交付

## 执行合同 C001

用户已确认独立新增、名称和业务目标编辑、查询、空需求删除及有关联来源时归档的范围。直接执行，不委派。范围包括 Store、SQLite/PostgreSQL 迁移、控制面 API/OpenAPI、同一前端的需求页面及来源接入、相关测试和产品文档。

- Collection 是独立持久化实体；旧来源按稳定 collectionId 无损回填，来源采集说明及不可变规则不改写。
- 编辑名称、业务目标只更新需求元数据。新接入来源使用当前业务目标；已有来源及已发布规则不自动重编译。
- 空需求允许工程师或管理员删除；有关联来源拒绝删除，可归档及恢复。归档是管理状态，不暂停或删除已有来源、运行、调度和数据；归档期间禁止添加来源及修改需求。
- revision 乐观锁保护编辑、归档、恢复、删除；数据库事务保护来源接入与删除/归档竞态；命令要求幂等键，权限由服务端执行。
- 需求命令、幂等回执与 AuditEvent 原子提交。重放不追加重复审计；前端在表单内容不变时复用创建幂等键，支持连接中断后的安全重试。
- UI：独立新建、详情编辑 Dialog、删除确认、归档确认、恢复、状态筛选和搜索；保存失败保留表单，冲突提示重新加载，不伪报成功。
- 使用现有 192px 侧栏、56px 顶栏、13px 正文、20px 详情标题及中性色/蓝色链接；操作使用 Lucide 和既有 shadcn Dialog，桌面 1024px 以上，无第二套前端。
