## 合同与执行顺序

1. P02–P05：不可变字段版本与历史查询，发布必须通过字段和 identity 语义校验、revision/权限/幂等/审计；新来源绑定固定版本，编译合同及运行均不读取可变草稿；保留旧静态合同兼容，不自动套用需求新版本。
2. P06–P07：迁移计划展示固定目标、差异与阻断；用户确认后进入待重编译/审核状态，活动规则和历史绑定保留，人工发布新规则后切换；运行中不得迁移，失败可重试或放弃，不能伪称已对齐。
3. P08–P10：少量版本化内置模板预览并应用为草稿；AI 建议复用默认模型网关、持久任务与调用审计，限制输入/输出、超时和活动任务数；建议先预览、选择后写草稿，不自动发布，refresh 恢复且 revision 冲突不覆盖编辑。
4. API/OpenAPI/类型、中文/英文桌面 UI、全套回归、双数据库与真实浏览器复核，更新当前合同与交付证据。

## Preflight 与校验

- Checklist：每个版本可追溯、已发布不可改；来源的当前执行合同和待迁移目标必须区分；AI 响应是不可信数据，不能直接执行；失败不能清空现有草稿/规则；版本和发布权限在服务端校验。
- Analysis：已有 Worker 对旧静态绑定回退到需求活动版本、未知版本静默降级，以及 expectedFields 仅作为模型提示，都不满足固定合同；优先用反例测试修正。已有版本发布与 UI 需要补齐权限、冲突、语义和失败路径证据。
- TDD：每批行为先增加失败测试并确认机制，再实现最小修复；已有代码先跑基线并补负向覆盖，不伪造既有实现的 RED 证据。
- 验证命令：`uv run --project backend pytest <相关 tests> -q`；隔离 SQLite/PG 全套；`pnpm --dir web test --maxWorkers=1`、`pnpm --dir web lint`、`pnpm --dir web build`、`pnpm --dir web api:generate`；manifest 与 diff 检查。
- 桌面：1440x900、1280x800、1132x1028、1024x800。真实写入验证使用明确独立的 G2 测试需求/来源，不修改既有用户对象；真实模型调用使用配置的供应商和仅用于本功能的测试需求，不存储凭据。

## Review 与完成条件

依次执行范围一致性、缺陷/安全/生命周期、浏览器交互验收。证据记录实际命令、RED/GREEN、修改、真实/合成数据与未测边界。P02–P10 必须逐项有完成证据，缺失则保持目标进行中；外部依赖不可用时报告实际失败，禁止模拟成功。工程完成不代替用户最终产品签收、G3/G4 或 1.0 发布。

## 界面设计合同

Standard / operational product refinement。需求详情仍以字段、关联来源两张工作面组织，头部版本状态与当前编辑状态分开。签名信息结构为「保存的草稿 / 已发布版本 / 各来源绑定」可比较但不混同，版本历史、模板、AI 建议通过紧凑工具入口按需展开，不增加装饰卡片或说明首页。

- 复用背景 #f5f7f8、内容 #ffffff、正文 #172126、次级 #65737b、边界 #d9e0e3、操作 #2557d6；绿色表示已对齐，黄色表示待迁移/审核，红色表示失败。
- 系统字体，页面标题 20px、分区 14–16px、正文 13–14px，字距 0；8/12/16/24px 间距，圆角不超过 8px。继承现有对话框和表格样式。
- 工具栏区分高频编辑/保存与按需版本/模板/建议，最小桌面宽度可有意换行；表格稳定列宽，长标识 title/截断，长说明换行，宽表局部滚动。
- 模板预览不写入；应用进入草稿。AI 建议有排队/生成/失败/可选择/已应用状态，逐字段勾选后才保存；生成期间允许继续工作，刷新恢复任务，过期建议显示冲突并可重新生成。
- 来源行并列实际绑定和目标版本；迁移对话框展示增删改及全部确认框，活动运行给出阻断原因；迁移后入口为重新生成、审核发布、失败重试和明确放弃。
- 交互复用 150ms 反馈与焦点恢复；切换版本只读查看，未保存输入不能被后台查询或建议完成覆盖。资产复用 Lucide 图标、真实字段/差异/采集证据，不新增营销图片。
- 验收重点：中英文四桌面尺寸、长字段、空/错误、角色、过期 revision、未保存保护及刷新恢复；无移动端工作。
