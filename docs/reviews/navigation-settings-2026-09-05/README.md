# 需求导航与设置体验验收

## 设计约束

- 面向桌面采集运营人员，采用既有控制台布局；需求定义业务目标，采集来源承载网站配置与执行规则。
- 需求列表进入独立明细，明细集中呈现目标、字段版本及所属来源；不将来源候选字段冒充需求字段合同。
- 设置采用 URL 同步的系统设置 / 模型设置页签，保留实际后端能力；切换、刷新、返回保持可预测。
- 沿用 192px 侧栏、56px 顶栏，正文 13px、详情标题 20px、间距 8/16/24px。白色底、#e1e6e9 分隔、#59676f 次要文字、#1d49bd 链接及既有语义状态色。
- 使用无卡片套叠的摘要与表格；列表目标最多显示两行，详情完整展示；链接悬停和键盘焦点提供反馈，页签使用 Radix 键盘行为。
- 使用既有 Extrio 品牌与 Lucide 图标，无装饰性图片或额外动画。加载、失败、缺失记录与只读权限分别呈现。
- 验证范围：相关交互测试、完整前端测试、构建、lint，以及 1440x900、1280x800、1132x1028、1024x800 桌面浏览器检查。

## 验收结果

- `pnpm test --maxWorkers=1`：27 个测试文件、103 个测试通过，覆盖需求列表到明细、同名不同 ID、返回搜索、失败重试、设置请求隔离、URL 历史和非管理员模型只读；原有模型、用户与采集策略测试通过。
- `pnpm build`、`pnpm lint`、`git diff --check` 通过；文档 manifest 校验通过。测试仍有两条既有 jsdom 文档导航未实现提示，不影响通过结果。
- 浏览器实际检查需求明细、添加来源的默认归属与取消路径、系统/模型页签及刷新恢复、中英文菜单和模型配置。保留真实 GLM / glm-5.3-flash 与密钥已配置状态，未调用模型或修改凭据。
- 四种桌面尺寸均记录实际 `innerWidth` / `innerHeight`，页面 body 宽度等于视口宽度，截图未见操作遮挡；控制台无 error / warn。
- 自动化在视口切换后的点击中误触 HTTP 来源开关，随即恢复为原始开启值，并重新读取界面确认；该操作可能更新策略审计时间，不改写历史记录。

## 评审与边界

设计检查通过：适配产品、首屏任务、信息层级、排版、桌面布局、状态、交互、内容真实性各 2 分；视觉记忆点与既有低对比次要文本各 1 分，共 18/20，平均 1.8。无营销式视觉要求，不接受移动端验收。

需求明细使用真实来源按 Collection 身份聚合，展示去重后的来源采集目标及版本元数据；不提供独立需求编辑或虚构字段合同。模板、AI 建议、手动字段与字段版本发布仍依赖后续领域/API 实现。浏览器验收未新增用户、来源、采集运行或模型调用。
