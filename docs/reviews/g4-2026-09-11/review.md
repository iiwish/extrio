# G4 技术复核

日期：2026-09-11。Direct Execute 自复核，非独立第三方审核。结论：下列已复现缺陷均有回归验证；当前证据不能批准正式发布，P28/P31 与产品签收仍是明确门槛。

| 风险 | 已复现问题 | 处置与证据 |
| --- | --- | --- |
| P1 | 空 PostgreSQL 库 API/Worker 同时迁移会冲突；SQLite 首连 WAL 亦可锁冲突 | Store 初始化在连接前使用 SQLite 文件互斥，PG 使用同库会话 advisory lock，覆盖迁移与回填；两库同步双子进程 RED → GREEN |
| P1 | 从 sdist 构建 wheel 时外部 LICENSE/合同路径不存在，安装制品不可用 | sdist 纳入 package-resources；自定义 wheel hook 从仓库或 sdist 选择资源；真实 `uv build` RED → GREEN，仓库外初始化验证 |
| P2 | single 模式实际提取成功但审核样本缺字段、低置信 | 构建候选时从同一单页合同填充 list_record；冻结合同回归 RED → GREEN |
| P2 | 单页审核样本计数显示为零 | 使用实际 previewItems 计数；组件测试 RED → GREEN，浏览器显示 1 |
| P2 | 发布确认显示固定的人名 | 取鉴权用户 displayName/username，不影响后端审计权威；组件测试 RED → GREEN，浏览器显示 G4 QA |
| P2 | 已发布字段仍显示尚未应用草稿 | 按不可变版本 ID 读取完整已发布字段，逐属性比较后展示状态；不从摘要猜字段；组件测试 RED → GREEN，双库刷新验证 |
| P2 | 投递已成功但已打开日志一直显示空 | 可见配置页每 5 秒刷新投递日志；测试先空后 delivered RED → GREEN，真实 HMAC 接收与浏览器状态交叉验证 |

完整版本字段查询在初次 Docker 类型构建中暴露摘要类型不含 fields，已改用现有完整版本 API；未增加平行客户端或绕过类型检查。单次 PG 浏览器等待曾在并行构建高负载下超时，检查发现写入已完成；最终将测试等待统一为 15 秒后完整重跑通过，未改变业务成功判定。

初始化锁仅处理启动路径，不更换正在运行的 G3 观测进程。SQLite 锁文件使用规范化数据库路径及 O_NOFOLLOW；PG 连接关闭释放会话锁。回退保留旧二进制、旧备份与匹配密钥，不把恢复能力简化为数据库迁移降级。

## 范围与残余风险

本包未变更迁移 SQL、协议合同、生产配置、模型凭据或自动发布边界。已保留基准以来 G1/G2/G3 的未提交工作，没有清理无关文件。文档中的运行手册与四份产品/前端/验收合同保持当前语义一致。

真实模型编译未验收；本机 Docker 架构不能外推为所有 CPU/宿主兼容；桌面抽样和基础键盘验证不能替代完整无障碍审计；旧版本升级矩阵只覆盖明确基准。72 小时观测未结束且运行版本为 G3。上述内容须随候选交付，不能通过“本地测试全绿”消除。

验收路径见 [验证证据](validation.md)，制品与退出状态见 [候选清单](release-candidate.md)。工程状态可进入 Needs_Review，产品 Accepted 和发布授权保持待确认。
