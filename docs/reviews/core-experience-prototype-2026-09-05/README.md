# 核心体验原型验收记录

日期：2026-09-05。结论：第一阶段原型制作与内部验证完成，等待用户评审流程和视觉方向；不代表 B0 至 B3 业务重构完成。

## 交付范围

- 独立入口 `web/experience.html` 与 `web/vite.experience.config.ts`，功能位于 `web/src/experience/`。
- 四个连续工作面：需求接入、规则审核、需求数据、异常恢复。保留现有五个一级导航的组织方式。
- 示例状态使用独立 localStorage 命名空间；发布、运行、修复和交付均为本地模拟，不调用生产 API。
- 复用现有 React、TypeScript、Tailwind、shadcn/ui 和 Radix，不增加运行时依赖。`web/.gitignore` 排除独立构建产物。
- 当前生产路由、后端业务逻辑与四份权威产品合同不在本次修改范围，已有工作区修改保留。

## 浏览器验证

使用 Codex 内置浏览器，通过 Playwright 接口和原生输入完成实际操作，不以静态截图代替交互验证。

| 路径或状态 | 观察结果 |
| --- | --- |
| 草稿编辑 → 刷新 | 字段名称修改保留，源合同未提前冻结 |
| 冻结 → 来源验证 | 城市来源进入待审核，省级来源独立显示缺失日期；没有自动发布 |
| 样本 → 字段证据 → 发布确认 | 侧栏保留来源与选中样本上下文；确认勾选前发布按钮禁用 |
| 失败来源 → 调整提取 → 重新验证 | 生成新候选，未验证时不能发布；详情日期提取验证通过后可审核 |
| 数据查询 → 实际导出 → 刷新 | “设备”与城市来源联合筛选为 167 条；实际下载 JSONL 包含 167 个唯一 ID，全部符合筛选，刷新后 URL 与查询保留 |
| 数据 → 来源规则 → 返回数据 | 恢复筛选、分页与选中的记录详情，组件测试覆盖完整往返 |
| 网络失败 → 恢复 | 重试完整运行；原失败运行与未推进检查点仍可见，恢复记录单独展示 |
| 交付失败 → 恢复 | 仅模拟重试 6 条交付，不重新采集网页 |
| 规则失败 → 候选 → 审核 → 恢复验证 | 必须经过重新验证和人工发布，不能从规则故障直接重试成功 |
| 跨标签页候选变化 | 第二个标签页修改候选后，第一个标签页的确认框出现过期提示并禁止发布 |
| 加载失败、加载中、无结果、无数据 | 加载失败重试与无结果在浏览器验证；加载中与无数据由组件测试覆盖 |
| 只读访问 | 可以查看样本与证据，不能修改、发布或恢复；英文界面保持相同权限边界 |

桌面 QA 使用 `1440x900` 与 `1280x800`。检查包括中英文、对话框、证据侧栏、可见焦点、Escape 关闭及关键操作的横向布局。1280px 下页面宽度为 1280px，检查到的按钮没有横向文字溢出；数据分页底部为 776px，处于 800px 高度内。长表使用内部滚动，接入提交栏保持可达。

## 残余边界

- 没有访问真实来源、模型或交付接收端；模拟验证不能证明真实采集准确率、漏采率或恢复可靠性。
- 六个字段、两个来源和 501 条记录为固定原型样本。字段版本迁移、任意规则语法及服务端全量查询仍需 B0/B1/B2 实现。
- 本地角色开关用于评审，不是生产权限系统；本地状态同步不替代服务端并发控制。
- 原型没有修改生产导出接口，不能把示例列表与导出一致性视为现有生产问题已修复。
- 尚未进行目标用户可用性测试；移动端按项目约定不在范围内。

下一步由用户确认三条链路的连续性、四个工作面的信息优先级与桌面密度，再确认首批业务实施范围。
