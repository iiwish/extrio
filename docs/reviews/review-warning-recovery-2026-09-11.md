# 字段审核阻断恢复入口

状态：Needs_Review。用户要求解释缺失字段的发布阻断，并补充提示与直接修复入口。采用局部直接执行，不委派。

## 范围与设计

- 目标：用户从具体字段警告发起已有 AI 修复任务，无需自行组织修复原因；不改变必填合同、字段决定或发布门。
- 来源审核区保持现有桌面密集布局与告警配色；每项问题使用无卡片嵌套的说明行和明确操作，字段技术标识可见，长模型标签换行。
- 主要操作为带 Wrench 图标的“修复此字段”，打开现有修复确认弹窗，自动填入该字段与警告上下文。次要操作保留证据查看。
- 原因说明区分“样本未验证”与“网页不存在”，解释可选字段排除及接受风险的后果。修复不保证成功、不直接发布；失败保持真实错误与重试入口。
- 新入口沿用工程师/管理员权限以及归档、活动任务和需求迁移限制；中文与英文一致，桌面视口 1440x900、1280x800、1132x1028、1024x800。

## 实现与验证边界

仅修改来源详情 UI、其样式、相关中英文文案、对应组件测试，以及四份产品/UX 合同与证据。复用 `/collectors/{id}/repairs`，不扩展后端能力或执行权限。浏览器验证只打开确认弹窗，不擅自重跑用户来源、不替用户排除字段或接受风险。

先添加针对字段上下文、取消不提交、真实修复请求、失败重试和不可用状态的测试，再实现最小变更。运行相关测试、前端全量测试、build、lint、文案一致性检查与上述四个桌面视口 QA。

## 验证结果

- TDD：新增的三个操作入口测试在实现前均失败（3 failed / 5 passed）；实现后确认了自动说明、取消不提交、调用修复 API 而非发布/字段排除 API、失败后保留用户编辑、归档不可用。补充只读角色不能发起字段修复测试。
- `pnpm test`：37 文件、194 passed，包含中英文文案一致性；`pnpm build` 与 `pnpm lint` 通过。测试使用隔离 API 响应验证真实客户端请求路径和幂等请求头，不触碰真实模型或用户来源。
- 浏览器在用户来源审核页确认新提示和字段操作可见，弹窗自动包含 `content`、当前缺失问题及保留合同约束；取消后焦点恢复到字段修复按钮。未启动修复、未改变字段决定、未发布候选。
- 1440x900、1280x800、1132x1028、1024x800 的审核区与修复弹窗截图均已检查，无遮挡或不可达操作。最小桌面弹窗为 384x364.71，坐标 (320, 217.64)，完整处于 1024x800 内；桌面 documentWidth 等于 viewportWidth，无横向页面溢出。长正文标签保持可读，已恢复用户默认视口。
- 四份产品/UX 合同已同步；未改后端或重启服务。`git diff --check` 通过，文档清单已更新。

余留边界：这是基于现有修复能力的明确入口，不保证模型一次修复成功，也不宣称该来源的正文缺失已解决；正文是否恢复必须以后续真实修复任务和样本验证结果为准。
