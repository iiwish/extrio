## 故障证据

来源 `collector_ggzyfw_beijing_gov_cn_53130add` 的操作 `op_x_1ff36ca2e9284b` 在 `fetching_list` 阶段失败，持续约 31.4 秒，尚未调用模型。入口请求返回 HTTP 200，但 Crawl4AI 的 `Page.goto` 等待 `domcontentloaded` 超过 30 秒，随后结果没有 HTTP 状态。适配器将空状态转换为 0，产生 `http_status_0`，Worker 最终展示笼统的网络/授权/结构失败。

日志同时记录了浏览器关闭后 `Route.abort` 的 TargetClosedError。现有记录不能确定具体哪个子资源拖慢了这次导航，不将临时加载超时归因为授权或模型故障。

## 实现

- `source_clients.py`：区分导航超时、有效 HTTP 拒绝和无响应加载失败。明确导航超时最多重试一次，两次尝试共享网络预算与边界；拒绝访问及越界错误优先，不自动重试。已关闭页面的迟到回调不污染后续尝试或产生二次路由关闭错误。
- `worker.py`：保存稳定受控原因，导航/请求超时给出明确说明与可重试标志；不输出第三方堆栈或源页面正文。
- `collector-page.tsx`：执行日志默认弹窗、收起按钮、状态入口、阶段时间、终态、错误代码与任务详情。收起不停止轮询，轮询不重新打开，新任务默认打开；刷新后最近 AI 日志按需查看。来源切换使用独立组件状态，避免旧来源日志遗留到另一来源。请求受理前的错误和配置保存错误仍在页面显示。
- `index.css` 与中英文词条：760px 最大弹窗宽度、视口内独立滚动、紧凑日志行；来源页头操作可换行，不挤压标题。四份产品文档与文档清单保持一致。
