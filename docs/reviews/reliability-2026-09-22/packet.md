# 可靠性交付包

## 范围与授权

任务 R1-R4 对应本次项目审查中的四项可靠性问题。用户明确要求修复上述问题；执行沿用审查提出的修复方向，不扩大产品范围，不发布镜像、不部署、不提交已有工作区修改。采用 Direct Execute，按任务顺序先建立失败测试，再实现和验证。

## 任务与验收

| 任务 | 实现边界 | 验收条件 |
| --- | --- | --- |
| R1 调度恢复 | app.py、store.py、调度回归测试及必要索引 | 领取后重启仍可派发；入队和派发标记同事务；失败回滚；并发派发不重复；业务阻断明确终结 |
| R2 迁移原子性 | store_dialect.py、迁移回归测试 | 外键检查发生在提交前；SQL 或校验失败均回滚数据、DDL 和迁移标记；外键约束恢复启用 |
| R3 发布门禁 | GitHub workflows、发布校验脚本及测试 | 核验目标提交及必需 CI；候选摘要通过扫描、签名后才提升正式标签；不得调用真实发布 |
| R4 有界启动 | store.py、独立回填模块、双数据库迁移、app.py、升级及启动测试 | 回填有版本标记且仅在显式迁移中执行；历史读取分批；普通重启不遍历历史；旧数据语义保留；失败可重试 |

R1-R4 均保持用户已有修改。R4 依赖 R2 的迁移原子性；CLI 的离线锁与 doctor 的未完成回填诊断属于 R4 的运维边界。不修改前端。必要的运维说明与本目录验证记录纳入允许范围。

隔离启动验收覆盖 `scripts/dev.sh` 的就绪边界：API/Worker 和 Web 均响应后才报告启动成功；不改变前端行为。

## 验证与完成标准

- 针对每项故障先运行失败回归，再执行相同测试确认修复。
- 后端 Ruff、完整 pytest、文档清单检查；PostgreSQL 使用独立临时测试环境，无法运行时明确记录。
- 发布校验通过离线 API fixture 和工作流结构测试，不推送标签或镜像。
- 最终复核 diff、故障边界和测试结果；未验证的远程发布或生产规模不标记通过。
