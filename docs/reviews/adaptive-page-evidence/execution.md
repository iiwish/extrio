## 真实模型与受控回归

真实模型仅调用一次任务：`ai_run_x_4940b97822ac4b878352cb3085730d`，当前配置 `glm-5.3-flash`，32K 保守默认配置，8 次调用、输入 34325 / 输出 1655 token、54.28 秒。任务在调用上限停止，保留 TITLE_MISMATCH 诊断，读取日志记录 12 次目录展开、0 个正文节点。无费用配置，未估算金额。详细记录见 `real-verification.json`。

这次实测暴露了目录提示过度偏向布局祖先的问题。回归增加深层正文和标题元数据直接可寻址测试，随后实现紧凑祖先路径、目录提示按样本均分，以及按剩余输入和请求数分配片段大小；验证反馈保留上次提案、已读状态和标题差异，审计只保留稳定字段。新增 RED/GREEN 测试同时覆盖表格跨片段表头与行范围、恢复停机时间计入预算、真实 usage 超限拒绝、任务 token 预算与模型上下文错误区分。

`offline-replay.py` 对该次保存的公开快照执行离线控制器与完整样本验证，模型为确定性 fixture，不调用真实供应商、不访问站点、不写业务数据库。8K 无调用即返回 MODEL_CONTEXT_INSUFFICIENT；16K、32K、128K 均使用 2 次受控调用，三个详情片段均进入模型输入，3 个样本通过、3 个实体标识独立、明细 URL 等于对应来源，固定合同一致。见 `offline-replay.json`。该证据证明预算与数据链路，不证明真实模型会作出相同选择。

通过任务前只读备份与当前数据库比较，原候选 digest、合同和活动规则指针一致，Item 总数不变。没有接受风险、排除字段、发布规则或执行生产采集。当前模型配置未被修改。目录改进后的真实模型复验需要新的明确授权；现有一次授权不重复使用。
