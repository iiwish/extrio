# 需求详情收敛

## P001 范围与设计

用户要求字段只显示一次，并打磨详情页。仅调整统一前端的需求详情与字段组件、对应测试和四份产品合同；后端字段草稿与发布边界不变。直接执行，不委派。

页面采用“采集字段 / 关联来源”两个页签。字段按 key 合并为一张表，来源差异在同一行的来源覆盖入口展开，不复制两个字段工作面。字段草稿与来源实际输出仍须明确区分，不能把聚合预览视为统一已发布合同；编辑从草稿或合并预览开始，保存仍是草稿。

收紧头部：移除重复眉题和四格统计带，标题下用单行元信息，目标在紧凑摘要中呈现。字段名和技术标识归入同一列，去掉全为空的业务说明列；类型、约束与来源覆盖固定列。颜色沿用中性色、蓝色操作、琥珀色差异，无新媒体、布局框架或后端命令。

验收：覆盖相同字段只出现一行、来源约束不同/缺失/不可用、草稿优先、原 CRUD 不回归。运行前端测试、构建、lint 和四种桌面截图；不修改真实业务记录。

## 验证证据

- 新增按字段 key 合并的测试先失败（mergeSourceFields 尚未实现），实现后通过。需求模块 4 个测试文件、17 项测试通过；前端全量 29 个文件、115 项测试通过。
- `pnpm build`、`pnpm lint`、`git diff --check` 和文档清单检查通过。后端 API 与持久化逻辑未修改，本轮未重复运行后端测试。
- 真实 API 的 5 字段与 7 字段来源按 key 汇总为 9 行；title、publishTime、detailUrl 各仅一行。detailUrl 的变更检测差异在同行标记，点击来源覆盖可核对双方约束及不可变规则版本。
- Playwright `desktop_qa.py` 在四种桌面视口通过：2 个页签、1 张主字段表、共享字段唯一、整页无横向溢出、弹窗在视口内、无页面 JS 错误；断言全程没有 POST/PATCH/DELETE 请求。编辑弹窗取消，临时浏览器关闭。

## 边界

同名技术 key 合并展示，不自动合并不同 key 的业务语义。来源汇总不是统一已发布合同；编辑保存仍为需求草稿。已保存的空草稿保持为空，来源额外字段仅按需展示，不会隐式补入草稿。来源合同及质量规则在单字段来源详情中按需读取，页面不复制第二张常驻字段表。
