## 复核结论

主代理审阅版本元数据、锁文件、升级 fixture、Compose 参数与清理路径、安全探针和文档合同。
生产变化限于版本号；schema 仍为 013，依赖版本不变。已记录 NLTK 风险之外，没有发现新增
可确认的 P0/P1/P2 缺陷。安全结论为有限测试边界，不是漏洞关闭或全局安全承诺。

两个执行代理独立交叉复核对方的高风险验证面：

- 安全代理审阅镜像摘要模式、参数引用、构建失败不回退、拒绝既有项目/卷与清理路径；归档 RC 的迁移、备份及恢复断言能区分原状态与候选新增状态。Shell 语法检查通过。
- 发布验证代理审阅六个 NLTK API 探针、预绑定别名、新线程正控制及异常被捕获后的记录，独立复跑 15 项通过；真实应用调用链未被 mock，模型配置与 completion 是 fixture。
- 文档复核确认升级 CLI 参数与现有实现相符，四份主合同、当前矩阵与 RC 发布记录区分稳定候选/已发布 RC，保留独立风险决策、最终签收和 72 小时观测豁免。

三处 P3 证据措辞在提交前收窄：canary 仅证明 HTML 无内容、文件/目录不变，不声称一般文件读取审计；
模型 fixture 同时覆盖配置和 completion；RC Container verification 属于原生 Linux 检查，
双架构证据只归属 Release 工作流。未用措辞修正代替应用测试。

## 证据强度

升级测试使用真实归档代码，但共用当前 venv；实际 RC 镜像另按正式摘要安装，禁止本地重建。
本地候选镜像是 arm64；远程 PR 原生 Linux 检查与未来正式双架构发布为独立门槛。
本地浏览器旅程以 production Web build、真实鉴权 API/Worker 和隔离数据库执行，模型为合成 HTTPS fixture。
完整结果、命令及测试限制见 [verification.md](verification.md)，产物身份见 [artifacts.json](artifacts.json)。

## 仍须决定

1. 用户对稳定版独立接受 [NLTK 限定残余风险](security.md)，或等待修复/另批依赖改造；告警保持 open，不新增忽略或降低门槛。
2. 候选 PR 必需 CI 检查通过，用户完成产品/技术签收，再批准合并。
3. 合并后精确 main SHA 检查通过；取得单独稳定版发布授权后，才执行 tag、双架构构建、扫描、签名和 provenance。生产部署不在本轮范围。

72 小时观测为已批准豁免，不作为长期稳定性或 SLA 证据。历史真实模型样本仅一公开来源；本轮没有新增调用或发布来源规则。
