# 统一列表分页

状态：已实现并完成桌面验收。范围包括所有一级对象列表，采用中等风险直接执行，不委派。验证记录见 [统一列表分页验收](../reviews/unified-list-pagination/verification.md)。

## UL-01 执行合同

- 采集需求、采集来源、采集运行、AI 任务、数据共享 ListWorkspace + ListPagination；容器拥有底栏，页面只提供查询状态、列与行内容。
- 共享 URL 分页状态与请求逻辑：每页 20/50/100/200，默认 50；筛选/排序/视图/页大小变更回到首页，刷新保页，详情返回保留页码，超界回落末页。
- 既有 API 未传 page 的调用保持兼容；新增按页查询、服务端全量过滤与准确总数。运行/AI 历史使用 SQL COUNT 与 LIMIT/OFFSET，不能把前 200 条作为全集。需求/来源的派生统计复用现有领域读取模型，在服务端过滤分页。
- 来源列表由服务端附带当前页的最近 Run，待处理判断不依赖前 200 次运行，归档/活动任务/待迁移/待审核等语义保持不变。筛选数量来自全量查询，不能由当前页推算。
- 不修改写操作、认证、采集、部署或数据库结构；保留全部已有未提交工作。
- 允许修改：共享列表组件和 hook、四个一级列表页面、API client/types/mock、只读查询模块与路由、OpenAPI、对应测试及产品文档。
- 验证：后端超 200 条分页与筛选/总数/边界/历史身份；前端所有列表替换分页、筛选重置、URL 与失败态；全量 web tests/build/lint、后端相关 tests、四种桌面尺寸只读浏览器验收。
- 视觉沿用现有 12px 辅助文本、32px 分页控件、白色列表、浅灰表头、8px 列表边界；工具栏/总数/底栏固定，仅列表滚动。无新增装饰图片或布局模式。
