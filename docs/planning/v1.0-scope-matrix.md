# 单组织自托管 1.0 验收范围

产品范围已获用户确认。本文件是 1.0 的版本适用合同，和产品合同中的 FR/NFR、发布验收中的 AC 一起使用；更广的平台设计目标不自动成为本版本的部署依赖。范围适用不代表能力已实现或验收通过。实现状态和证据由 [交付规划](v1.0-delivery-plan.md) 的 P01–P32 与工作包验证记录维护。

## 产品与部署

- 一个组织、一个实例，本地 administrator/engineer/reviewer/viewer 账号及服务端可撤销会话。组织标识、对象归属和权限检查保留，不承诺多个租户之间的隔离服务。
- 唯一 Web 前端，中文和英文，仅支持宽度不小于 1024px 的桌面。主验收 1440x900，补充 1280x800、1132x1028、1024x800。
- PostgreSQL 为自托管部署路径，SQLite WAL 为评估及本地开发路径。API 与 Worker 共用同一数据库，数据库持久化队列及租约；受限浏览器由运行进程管理。
- 签名密钥、独立凭据加密主密钥与 Artifact 目录由实例运维负责保护、备份和恢复。G3 必须验证权限、失效、恢复与部署检查；本地文件存在不等于运维验收通过。
- 来源限于支持样本覆盖的公开或已授权入口，支持 HTTP 和受限浏览器、single/list_detail 与声明的分页方言。拒绝任意代码、绕过访问限制、任意网站兼容和无人审核自动发布。
- 后续平台范围：多租户、OIDC/SSO/MFA、分布式 HA、Redis Streams 集群、Kafka、对象存储集群、托管 KMS/HSM、模板市场、云托管和移动端。既有相关契约保留为后续设计依据，不宣传为本版本已验证能力。

## 验收场景与退出

AC-001–007、AC-010、AC-012、AC-014–017 在上表的单组织部署边界内必验。AC-008 验 Webhook，Kafka 为后续；AC-009 按实际证据等级、权限和本地保留/恢复验收，缺少完整回放材料时必须拒绝等价回放；AC-011 验本地角色、归属和脱敏，SSO/MFA/跨租户部署为后续。AC-013 保留性能、容量和 RPO/RTO 演练，按本文件区分短期实测与长期 SLO。

进入验收需要一致的 API/Worker/数据库、独立测试账号与已批准来源/模型、Webhook 测试接收端、备份目录与密钥、故障注入能力、可校验的候选制品。Kafka、Redis、Secret Manager 与对象存储集群不是 1.0 的前置依赖。

P01–P32 在适用范围内逐项有证据；P0/P1 为零，P2 需产品负责人明确接受影响与期限；双数据库升级、真实有鉴权旅程、代表性来源/模型、72 小时观测、备份恢复和候选版本回滚完成。UI 工程交付不代表用户设计签收，单元测试不代表正式发布。禁止宣传尚无证据的全站兼容、月度 SLA、平台容量、等价回放、灾备达标或多租户能力。最终 Accepted 由产品与技术负责人确认。
