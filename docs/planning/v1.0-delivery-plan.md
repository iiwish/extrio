# Extrio 1.0 开发规划与任务估算

日期：2026-09-11。状态：范围已确认，G1、G2 技术验收通过，G3 工程交付完成；G4 本地工程进入 Needs_Review，集成、双数据库升级回退、桌面验收与候选制品验证通过。P28 真实模型、P31 完整观测和用户签收仍待完成。用户确认先交付单组织自托管稳定版，并要求全站页面的内容、布局与交互获得系统性打磨。依据当前工作树、产品合同、项目健康检查及已完成工作包的实际执行结果；预算不代表未经测试的能力已经完成。

## 结论

本轮交付按 **4 个约 3 小时的大工作包、合计 12 小时目标预算**组织，包含全站体验、功能补齐与稳定性验收。G1、G2 已通过技术验收，G3 工程交付完成；G4 暂保留 **3 小时执行目标**，另保留 **1–2 个按实际缺口启用的补充包（3–6 小时）**。这些数字是规划假设，不是具有统计依据的完成区间；G4 的真实来源、升级矩阵、观测分析和用户复核仍存在不确定性，不能承诺第 4 包必然达到发布条件。

两个已完成目标分别用时 1,343 秒与 1,324 秒，合计约 **44 分 27 秒**，来自目标工具的累计执行墙钟时间。它们覆盖需求列表和详情的体验改进，包含相关测试和桌面浏览器检查；目标未设置时间预算。这个样本支持扩大后续目标，不支持把所有后端、迁移和运维工作按同一倍率压缩。

P01–P32 是验收工作项，不是各自占用 3 小时的任务。一个大工作包包含多个相关工作项，按完整用户成果组织，统一实现、联调与复核，避免每个小改动重复启动和交接。已有能力先验证再补缺，不从零重建。全站体验的覆盖和质量标准见 [全站体验工作流](v1.0-experience-workstream.md)。

估算从 D1-W2 工程交付后的状态起算，不重复计算已完成工作。有效执行与外部等待分别记录：真实站点/模型授权、用户复核、72 小时持续运行观察不计入 12 小时执行目标，但仍影响正式发布日期。本文件不创建目标、不调度自动执行，也不授权删减已确认范围。

## 已确认的 1.0 范围

目标用户是一个组织内的数据运营团队；交付一个实例、一套本地账号角色体系、一个受支持的自托管拓扑。支持桌面 `1024px` 及以上、中文/英文、已声明边界的公开或已授权列表/详情来源、HTTP 和受限浏览器。保留现有 SQLite 评估路径和 PostgreSQL 部署路径。

闭环包括需求字段草稿、可审核且不可变的字段版本、来源绑定与受控迁移、AI 辅助接入、人工发布、定时/手动运行、数据变化与交付、失败诊断、证据检查和已验证的备份恢复。首批模板以少量内置审阅模板交付，不承诺模板市场或通用 SDK 生态。

多租户、SSO/MFA、分布式 HA、Kafka、托管 KMS/HSM、云托管服务、移动端或任意网站采集不属于本次 1.0 范围。FR/AC/NFR、部署依赖与禁止宣传能力见[版本适用合同](v1.0-scope-matrix.md)。范围选择不等于所有 AC/NFR 已实现或验收通过。

## 执行与重估规则

- 执行前用一份工作包列清该包成果、允许修改范围和必要验证，不为每个布局或文案改动建立独立目标。
- 每包约 60–90 分钟检查一次覆盖进度和剩余风险，继续推进未完成条目；提前达到全部验收条件即可结束，不为凑够 3 小时做无关工作。
- 每包交接记录实际墙钟用时、完成项、未完成项、测试与浏览器证据、外部等待以及剩余估计。完成率按验收成果判断，不按文件数、代码行数或勾选条目数机械计算。
- G1 后校准批量页面改进的吞吐；G2 后用字段发布/迁移的真实数据重估总包数。两个小型前端样本不能充当后端复杂任务的速度样本。
- 达到约 3 小时时验收未齐，保留未完成状态，具体缺口进入重估；不自动关闭目标或把未测能力标记完成。3 小时是规划检查点，不是强制运行时限。
- R1 补充包优先承接 G2 的模型、迁移或 AI 闭环缺口；R2 优先承接 G3/G4 的恢复、兼容或集成缺陷。只有发现具体未完成项及必要验证时才申请启用，不预先消耗缓冲。
- 若缺口超过两个补充包，直接报告新的证据和估计，不把 18 小时当作必须达成的上限，也不通过降低验收标准维持数字。

关键依赖仍为 P01 → P02–P07 → P27 → P29/P30 → P32，具体工作项按上表前置执行。共享 Store、OpenAPI、生成类型和同一工作树的修改需要串行整合。文档 P01 对范围的映射不能扩大已批准目标；支持边界有歧义时由用户确认。

## 后续平台范围

多租户隔离、SSO/MFA、分布式队列与高可用、对象存储、托管密钥和 Kafka 属于后续平台规划，不计入本轮预算。启动这些能力前单独确认产品合同、架构、风险和工期，不按本轮页面打磨的吞吐外推。

## 退出条件

- 经批准的 1.0 范围逐项有实现和真实证据，未实现能力不报告成功。
- P0/P1 为零，P2 有影响、负责人、处置期限和产品负责人的明确接受。
